# 74 产业环节与企业身份分开建模

## 一句话

> 允许AI提出有用的公司候选，同时单独核对代码和真实资料，不把模型建议直接当证券身份或供货事实。

## 为什么需要它？

旧结构图禁止任何公司名称，结果只有抽象环节。简单放开后，又可能出现公司名正确、股票代码错误，
或把“参与同一产业”说成“互相供货”。解决办法是结构、候选、身份与来源各自负责一件事。

## 项目里的真实代码

`backend/chain_companies.py` 让模型选择node_id、公司名、业务及影响力理由；URL不能由模型生成。
程序匹配已收录官方资料，或用既有company_context按候选代码查询公司资料。只有名称匹配才附A股代码。
查不到资料保留AI候选，公司列表不会因一家源失败全部不可用；官网摘要只支持业务介绍，影响力仍是判断。

缓存键包含板块代码/名称、完整草图内容、模型、提示及目录内容；更新失败在写入前退出，旧记录不被替换。
`frontend/components/sector/chain-companies.tsx` 单独显示企业，图继续可用；默认不做失败自动付费重试。
缓存命中不查公司源、不调模型，也不把读取时刻改成新的生成时间。
首次请求网络中断时，服务器可能已经完成生成，因此重试仍先读缓存；只有用户主动更新或损坏记录修复才强制生成。
缓存再次读取时也验证股票代码对应的来源网址和公司名称，防止损坏记录把正确公司名链接到另一只股票。

## 自己试试（5分钟）

1. 运行 `python -m pytest tests/test_backend/test_chain_companies.py -q`。
2. 看身份返回“另一家公司”时，名称仍显示为候选，但不会出现错误股票链接。
3. 看refresh失败后，默认请求仍能读取原结果且时间不变。
4. 在BK1184页面展开绿的谐波资料，查看官网业务描述与新浪名称/代码依据分别负责什么。
