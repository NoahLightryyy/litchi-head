# 70｜证据时间与缺项阻断

一句话：相关资料可以先展示，来源与日期说明它是什么；只有形成核验证据和完整执行输入，才进入对应的判断与计算。

本项目 `backend/policy_capital_contract.py` 将持仓报告期与披露日期分开，保留净值权重和披露覆盖范围；2026Q1的中微4.29%不能当今天的完整ETF敞口。政策成文日也不能代替生效日。

ExecutionPreview在blocked时强制数量、费用、余额都为空；ResearchJob要求终态负载一致。Pydantic验证结构，不能替代原文核验与服务端引用、身份校验。

## 2026-10-26：把资料检索与核验证据分开

原页面只查三个静态证据包，没有对应包的股票和ETF就显示空卡。它把“还没有专属核验结论”误用成了“相关资料也不能展示”。现在默认调用 `GET /api/research/related`，查已有资料；已核验证据、付费AI深入研究及本金约束保留在独立折叠区域。

`backend/related_keywords.py` 根据名称、股票主营资料和主题词确定性提词，不调用LLM。例如“半导体设备ETF广发”提取“半导体设备”，扩展“半导体、集成电路、芯片”；“设备”这种宽泛词不会关联所有行业。用户填写关键词时覆盖自动词，多个词按任一匹配；“铜”“锂”等单字中文可作为手动查询。股票的新浪主营资料获取失败，仍按名称与代码检索。

`backend/related_research.py` 检索近365天已入库的 `news_archive` 报道和已归档政策。每项保留原链接、发布日期、命中词及关联理由，区分“直接提及标的”与“主题相关”。检索时间单列，不能替代文章发布日期；较早的归档政策也保留原日期。标题或链接相同的资料去重，转载不因出现多次就变成多份独立验证。

这里的自动化只是已有材料检索，不是全网搜索、最新政策全集或自动核验。它不产生LLM研究费用，也不生成新证据包。正式证据包仍只有 `BK0917`、`688012`、`512480`，历史持仓、AI结论与本金计算的约束继续有效。

自己试试（约3—5分钟）：

1. 打开ETF `560780`，查看自动关键词、文章日期、链接与匹配理由；输入“出口管制”，确认自动主题词不再混入此次查询。
2. 运行 `pytest tests/test_backend/test_related_keywords.py -q`，对照提词测试中的相关与无关行业、ASCII边界和单字中文查询。
3. 运行 `pytest tests/test_backend/test_policy_capital_contract.py -q`，把历史持仓日期改为披露之后，或给blocked填200股，观察验证失败。检索可用性没有放宽金额计算约束。
