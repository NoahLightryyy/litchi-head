# 72｜把新闻摘要变成可追溯的产业研究

## 一句话

新闻提供“报道了什么”，产业研究解释“经过哪些环节、在什么条件下影响经营”；
两层需要分开保存，让后续分析能复核而不是反复引用AI自己的结论。

## 项目里的问题

688648的关联检索会同时返回物流网政策、多家转载、券商解读以及只命中“运输”的国外报道。
直接逐篇生成利好标签，会重复计算同一事件，并把弱关联误当公司已受益。
旧减持计划也可能在窗口结束后被误写成当下抛压。

## 实现方式

`backend/related_interpretation_contract.py` 将 `summary` 固定为报道复述，
其引用只能指向保存快照中title/excerpt的原有文本。
`impact_path`、`affected_scope`、`duration`、`market_reaction`、
`business_realization`、`subject_relation` 均固定标为AI推断。

`backend/related_interpretation.py` 对每篇输入要求恰好一次归属：一个事件或排除记录。
这保证没有悄悄漏掉输入，也不会把同一篇文章计算进多个事件；
它不证明模型对不同转载已经正确归并，也不证明引用覆盖了摘要所有语义，仍要真实样本复验。
引用子串校验只能证明来源里存在这句话，不能证明这个政策导致未来股价上涨。

复制引用和选错来源要分开处理。新生成结果先校验所有来源确实存在、归属正确且没有遗漏重复；
若仅是模型把同来源原句的标点或文字复制错，服务端直接从该字段截取真实片段替换，最多300字，
空节选退回同来源标题，并在限制说明中标注。错误的模型引文不会展示，也不用为这类问题重跑整篇。
来源 ID 不存在、跨事件引用或旧缓存被篡改仍拒绝。此处理不改概况文字或事实状态，
更不证明截取片段能支持摘要全部含义；保存和读取阶段仍严格检查真实子串，不自动修补缓存。

正文范围必须按实际读取的材料来讲：新闻节选可能只有标题；档案摘要也不是政策全文。
单源或只有标题仍可进行有限解读，在相应维度写具体缺口即可。

市场反应和经营兑现是两条时间线：情绪与估值预期可能先变化，
订单、投产、交付、确认收入需要后续条件；没有事件窗口行情和预期证据时不能断言已经或尚未定价。
政策原文写2030年目标，不能直接推成公司将受益到2030年。

## 模型返回之后还要校验什么

这次实测遇到 HTTP 成功、返回元数据写 `tool_calls`，但结构化解析没有对象的情况。
没有保存原始响应，就不能据此认定是函数名错误、模型不支持复杂结构或具体哪个字段丢失。

本功能通过 `src/utils/llm.py::invoke_structured` 显式选择 `output_method="json_mode"`：
请求 `json_object`，把完整 Pydantic JSON Schema 放进系统消息，再对收到的完整文本执行
`model_validate_json`。默认工具调用路径保持原样。这里的三层检查分别回答：

1. JSON 和 Pydantic 结构完整吗？空响应、普通文字、字段缺失、截断都不能保存成功。
2. 引用在快照里吗？句子必须为对应标题或节选的连续子串，所有输入资料恰好归属一次。
3. 解读语义有依据吗？结构和子串检查无法替代这一步，仍需真实案例检查归因、时间和适用边界。

不能为让页面显示成功而补上被截断 JSON 的括号，因为被截掉的可能还有事件、限制或排除理由。
收到消息后先记录用量，因此解析失败也不等于没有产生模型费用；解析失败不会再自动发一次生成。
具体症状与处理见 [LLM 结构化输出急救](../01-guides/triage/llm-structured-output.md)。

## 后续分析如何复用

GET与 `format_saved_interpretation` 仅读取明确的kind/code/q成功快照；
默认辩论只取q为空的自动主题，保留生成时间、出处与AI推断标签。
新的原始财报、新闻和行情优先于旧AI文字，读取不会触发又一次模型费用。

## 自己试试（5分钟）

1. 看 `tests/test_backend/test_related_interpretation.py` 的引用和快照隔离测试。
2. 在生成 mock 中改错同来源的quote，确认换成真实片段并显示说明；再篡改已保存quote，确认读取拒绝。
3. 将同一来源同时归入两个事件，确认不能保存为成功结果。
4. 在页面切换关键词，再返回默认提词；检查两份解读不串用，日期与原文链接保留。
5. 运行 `python -m pytest tests/test_utils/test_utils_llm.py -k explicit_json_output`，
   看 mock 测试如何拒绝缺右括号及 `finish_reason=length`，此测试不调用真实模型。
