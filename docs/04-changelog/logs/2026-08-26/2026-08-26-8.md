# AI 工作日志 — 2026-08-26 多窗口并行开发规则补强

## 背景

前端与后端窗口同时在同一工作目录推进，暴露出一个现行流程缺口：项目已经规定前端消费
后端契约、OpenAPI 与 TypeScript 需要同步，但没有硬性要求不同可写窗口使用独立 worktree，
而 `AGENTS.md` 和 CI 流程仍默认使用 `git add -A`，存在把其他窗口未完成修改混入提交的风险。

## 本次改进

- 新增唯一规则 `workflow/CONCURRENT-DEVELOPMENT.md`；
- 硬性规定“一可写窗口一 worktree + `codex/` 分支”，`main` 只作为稳定集成线；
- 明确共享/来源不明脏工作树禁止切分支、合并、变基、整体 stash 和 `git add -A`；
- 提交改为 `git add -- <本任务明确路径...>`，并强制检查 staged 文件与 diff；
- 冻结“后端契约测试 → Pydantic/OpenAPI → 原子提交 → 前端适配 → 集成验收 → main”顺序；
- API 未冻结时前端标记 `🔒 待上游`，不得猜字段或伪造时间；
- 同步启动、开发、收尾、CI、前端总表、后端主管表、跨部门/前端/QA 交接；
- 清理现行 triage 和历史实施计划中的危险 Git 命令引用；
- 新增学习卡片 53《多窗口开发为什么必须隔离工作树》。

## 债务与验证

流程缺口在本次会话内直接修复，没有新增技术债务。未修改产品代码，不运行产品测试；
通过全项目现行规则引用搜索、Markdown 链接目标检查和 `git diff --check` 验证。

## 后续执行
