## README 公共状态同步 Fix Round 1

- 审查发现 GitHub Actions 只直接运行 Ruff、Pyright 和 Pytest，PR 可绕过本地 README

  可错误掩盖更晚的 canonical 状态变更。
- `scripts/check.py` 现按比较 ref→`HEAD` 的逐提交批次（旧→新）再加当前未提交批次处理；
  同批或更晚 README 关闭 pending，随后 canonical-only 变更会重新失败。新增 `--readme-sync`
  专用模式，不运行依赖安装、Ruff、Pyright、Python 测试或前端检查。
- `.github/workflows/ci.yml` 的 check job 使用完整历史，并仅在 PR 中以 base SHA 调用该专用

## README 公共状态同步 Fix Round 2

- 复审发现默认 `git diff-tree` 不报告 merge commit 的路径；冲突解决只修改 canonical
  文档时，较早 README 仍可能掩盖更晚的变更。
- `git_commit_batches()` 现在读取 commit parents：线性提交保持原路径差异；merge 分别计算
  merge tree 相对每个 parent 的路径集合并取交集，仅把冲突解决/merge 自身相对所有 parent
  都不同的路径作为该批次变更。纯 incoming 路径不误触发；已定位 commit 无法读取时门禁
  fail-closed，而无 upstream 仍只检查当前未提交批次。
- TDD RED：`python -m pytest tests/test_scripts/test_check.py -q` 为
  `3 failed, 30 passed`；真实临时 Git 仓库的冲突合并证明 merge 批次被错误算为空。
- GREEN：同一命令为 `33 passed in 1.60s`，覆盖真实冲突解决 canonical 路径、incoming-only
  路径不误报和不可审计 commit 的 fail-closed；Ruff、Pyright 与 `git diff --check` 通过。
- 完整闸门：`python scripts/check.py --full` 5/5 通过，1734 collected、1711 passed、
  4 skipped、19 deselected；Ruff、Pyright、README sync 与前端类型检查通过。

## README 公共状态同步 Fix Round 3

- 复审发现 merge batch 交集虽排除了 incoming-only 路径，但原提交遍历仍会收集被合入分支
  的历史 commit，导致这些路径先进入 pending。
- `git_commit_batches()` 改为 `git rev-list --first-parent --reverse`：仅沿当前分支主线收集
  batch，并保留 merge-parent 交集语义，以继续捕获真正的冲突 resolution。
- TDD RED：`python -m pytest tests/test_scripts/test_check.py -q` 为
  `2 failed, 31 passed in 1.71s`；真实 incoming-only merge 的完整 batches 含 ROADMAP。
- GREEN：同一命令为 `33 passed in 1.55s`；完整 batches 不再含 incoming ROADMAP，且
  `missing_readme_sync_batches(batches)` 为空；冲突 resolution 的完整 batches 仍返回 ROADMAP pending。
- Ruff、Pyright、`git diff --check` 与 `python scripts/check.py --full` 均通过；完整闸门
