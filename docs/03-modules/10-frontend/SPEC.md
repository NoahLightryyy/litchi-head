# 前端规格

## 1. 产品定位

专业散户一站式投资决策工具。以「自上而下决策漏斗」为核心交互模型：
宏观抓方向 → 板块找赛道 → 产业链定标的 → AI 辩论助决策。

## 2. 页面规格

### 2.1 Page 1: 宏观总览 `/`

**功能点**：
1. 三大指数实时行情（上证/深证/创业板）
2. 板块排行榜（按 `meta.sort_applied` 展示真实排序；资金流缺失时保持来源顺序；默认仅展示前 10 条，其余由用户展开；请求超过 18 秒进入可重试失败态）
3. AI 宏观简报（LLM 自动生成当日的市场风格、热点、风险提示）
4. 关键词搜索（快速定位板块或个股，支持 autocomplete）
5. 热点快讯流（滚动）
6. 点击板块 → 跳转到 `/sector/[id]`

**数据源**：`backend/api/market/overview` + `market/sectors`

### 2.2 Page 2: 产业链分析 `/sector/[id]`

**功能点**：
1. 板块头部信息（涨跌幅、主力净流入、热度标记）
2. 产业链地图（上游 → 中游 → 下游，关键节点标记 ⭐）
3. 板块个股列表（可排序：AI 评级/资金流向/涨跌幅/市值等）
4. AI 产业链分析（自动分析产业链关键环节与不可替代企业）
5. 点击个股 → 跳转到 `/stock/[code]`

**数据源**：`backend/api/market/sector/{id}` + 本地产业链知识库

### 2.3 Page 3: 个股决策 `/stock/[code]`

**功能点**：
1. 实时行情卡片（价格、涨跌幅、成交量、换手率、主力净流入）
2. K 线图全宽主区域（Lightweight Charts）
   - 周期切换：日/周/月
   - 可叠加指标：均线(MA)、RSI、MACD、布林带
   - 历史蜡烛只包含 `FINAL_DAILY`；今日动态蜡烛单独标记“盘中形成中”
   - 正式指标与“含盘中估算”指标分栏/分标签，禁止静默覆盖
3. Tab 切换面板：
   - **技术分析**：指标详情 + 技术信号
   - **资金流向**：主力净流入趋势、大单追踪
   - **AI 辩论**：触发辩论 → 展示大师分析 + 共识评级
   - **信任度**：大师历史准确率 + 校准曲线
4. 关联新闻流
5. 「重新辩论」按钮

**数据源**：`backend/api/stocks/{code}` + `/kline` + `/news` + `/debate`

## 3. 路由规则

| 路径 | 页面 | 参数 | 说明 |
|:-----|:-----|:-----|:-----|
| `/` | 宏观总览 | — | 默认首页 |
| `/sector/[id]` | 板块详情 | `id` = 板块代码 | 资金流缺字段时为 `null`，不得显示为 0 |
| `/stock/[code]` | 个股决策 | `code` = 股票代码 | 支持 `?tab=debate` 默认 Tab |

## 4. 状态管理

| 状态 | 存储 | 存活期 | 用途 |
|:-----|:-----|:------:|:-----|
| API 缓存数据 | TanStack Query cache | 5-30 分钟 | 行情、板块、K 线等非关键实时数据 |
| WebSocket 行情 | Zustand store | 会话 | 实时价格推送 |
| 导航历史 | Zustand store | 会话 | 面包屑、最近浏览 |
| 辩论结果 | TanStack Query cache | 会话 | AI 辩论结果 |
| 用户偏好 | localStorage | 持久 | 默认 Tab、排序偏好 |

## 5. 加载策略

| 场景 | 表现 | 技术 |
|:-----|:-----|:-----|
| 页面初次加载 | 骨架屏(Skeleton) | `loading.tsx` 或 Suspense |
| API 请求中 | 局部骨架/Spinner | TanStack Query `isLoading` |
| API 请求失败 | 错误卡片 + 重试按钮 | TanStack Query `onError` |
| K 线图加载 | 占位图 | Lightweight Charts loading API |
| 辩论进行中 | 进度条 + 阶段指示 | 轮询 `/api/debate/status/{id}` |
| 今日 K 线未收盘 | 正常允许启动 AI；显示实时价、分时和“盘中形成中”动态 K | 分层证据 API |

## 6. 错误处理

| 错误类型 | HTTP 状态 | 前端表现 |
|:---------|:---------:|:---------|
| akshare 无网络 | 503 | 显示「数据源不可用」+ 使用缓存 |
| 股票代码不存在 | 404 | 显示「未找到该股票」+ 搜索提示 |
| 辩论超时 | 504 | 显示「分析超时，请重试」+ 按钮 |
| LLM 调用失败 | 502 | 显示「AI 服务暂时不可用」+ 缓存常用分析 |
| K 线/盘中证据不完整 | 503 | 显示缺失层、来源、时间与重试建议；不展示旧结论冒充本次结果 |

### 盘中状态展示不变量

1. `FINAL_DAILY` 与 `PROVISIONAL` 必须有文字标签，不能只靠颜色区分；
2. 动态 K 显示 `as_of` 和“仍会变化”，收盘多源确认后才转成历史蜡烛；
3. 页面不得提示用户“等待日 K 收盘后才能分析”；
4. AI 结论中引用盘中动态状态时，前端保留对应状态标签。

## 2026-10-22 首页备用源提示

用户确认多源用于可用性兜底：任一有效源即可展示。指数来源整批有一个 healthy 时，仅备用源失败归为 healthy_with_warnings，连接状态正常，失败详情折叠保留。三指数齐全、非缓存且无冲突/其他限制时，来源失败不显示黄色横条。缺失、陈旧、刷新失败、冲突和其他业务故障仍显式提示。后端健康契约与正式 AI/风控门禁不变。

## 2026-10-26 搜索页资金备用

默认显示同花顺个股资金净流入及可选来源周期，即时/3/5/10/20日。东方财富主力/总流入榜保留在
独立折叠区域，其失败不阻止同花顺显示。来源缺数据日期时明确标注，采集时间另列。
指标、来源、币种与周期严格校验；刷新失败可保留同周期最后数据并提示，切周期不得沿用其他周期结果。

## 2026-10-26 行业页可用性与提示密度

两路现有板块请求仍独立并发；有数据且无请求失败的榜单优先展示，其次部分缺口、历史快照、空榜。
partial中的来源口径说明不等同请求失败；新浪净流入不因缺主力字段而被判不可用。
行情时间、离线、实际刷新失败与未知限制继续显式显示；缓存/历史/延迟不重复告警。
HTTP502、行业层级和单目录项无报价进入默认折叠详情；正常快照及统计说明使用中性样式。
选择行业或概念时按failed_sources分类投影状态，另一分类失败不污染当前成功分类。
全局健康异常保持原分类及状态点，详细端点诊断折叠；空结果与调用失败分开显示。
本轮不修改后端契约、财务计算、数据时间、来源或资金口径。

## 2026-10-26 详情页相关政策与资讯

股票、ETF、板块详情页的研究卡默认展示“相关政策与资讯”，调用
`GET /api/research/related?kind=…&code=…&name=…&q=…`。名称、主营资料和主题词用于确定性提词，
界面显示关键词，可点击词检索，也可编辑后提交或恢复自动提词。用户输入覆盖自动词；
多个词用空格或逗号分隔，匹配任意一个即可，支持“铜”“锂”等单字中文。

范围为现有近365天新闻档案及已归档政策；每条显示来源、发布日期、原文链接、匹配词及理由，
区分“直接提及标的”和“主题相关”。文章日期与此次检索时间分别展示，不能把历史政策显示成当日新政策。
股票新浪主营读取失败时按名称与代码继续查询，其他来源成功的数据照常展示；
来源诊断可展开。加载、无匹配、离线和失败状态分别展示；刷新失败可保留同一检索的已有结果，
切换标的或关键词后不沿用其他查询结果。

检索只读取已有材料，不调用LLM、不产生AI研究费用，也不代表全网搜索或已核实政策受益。
“已核验证据与 AI 深入研究”和“本金执行约束”各自默认折叠；没有专属证据包不阻挡上方相关资料。
正式证据仍只有BK0917、688012、512480三个包，检索结果不改写证据包、不触发付费任务或本金计算。

## 2026-10-26 ETF K线与多轮辩论

ETF详情按报价、K线、多轮辩论、相关资料、折叠来源排列。K线请求最多730日原始日线，
本地聚合日/周/月，价格三位小数、量为份。当前来源有效就显示，不因另一个来源失败降级。
刷新失败保留同基金成功图与实际数据日期；空数据、换基金和初始失败各自处理。

DebatePanel复用股票的完整分析结果、同侪/独立复核、历史恢复和刷新保护，显式传instrumentType=etf。
历史查询、缓存、任务结果均按类型+代码隔离；历史缺类型只能属于股票。
未取得净值/持仓等不会阻断已有材料的主题研究，也不将这些未知值编造成基金事实。

## 2026-10-26 搜索页排行榜分页

个股涨幅榜、同花顺资金净流入榜、折叠的东方财富主力／总流入榜统一每页10条，
各自展示条目范围、总条数和页码，通过上一页／下一页切换。页码互不影响；切换统计周期或
资金口径回第一页，刷新后条目变少时限制在有效页内，空榜不显示分页控件。
分页在已返回数据上切片，保持完整来源排序与尾部条目，不增加翻页网络请求。
来源“前20／前50”的范围说明保持原义，不改成每页数量；已有缓存和刷新失败提示仍保留。

## 2026-10-26 入场信号与资金计划

用户批准股票与ETF的三周期入场信号、仓位、止损和分批计划。新面板优先于方向分布，
绑定当前辩论session与品种身份，默认只读取保存结果，点击生成／更新才调用独立计划接口。
API以 `docs/03-modules/08-backend-api/ENTRY_PLAN_CONTRACT.md` 为准。

按短／中／长期选择查看触发条件及达成状态、入场区间、止损依据、失效条件、分批比例与触发事件。
核对状态为AI根据列明资料时间的判断，不声称持续监测；来源和原研究日期可展开。
旧方向条件不直接转换成买入信号；刷新失败保留旧计划及生成时间，切会话清理旧计划。

账户总资产、现金、总投入上限、现有持仓与此次新增可承受亏损留空，用户填写后本地确定性试算。
候选价可用于预填并允许编辑；用户修改不会改变AI条件状态。输出金额、占比与各批金额，
未接交易规则／费用核验时不输出可成交股数。费用、滑点、跳空和既有持仓风险不计入新增风险公式。

行情数据时间在条件旁直显；各批金额按同一输入价格估算，后续批次价格改变时须重新计算。切换周期或更新计划清空资金输入，避免沿用另一方案的风险数值。
