# ADR-013：多源证据完整性与 LLM 前失败关闭

| 字段 | 值 |
|:--|:--|
| 日期 | 2026-07-28 |
| 状态 | 🟢 决策已批准，分批实施中 |
| 影响范围 | data / debate / agents / memory / risk / trading / backtest / backend / frontend / infrastructure / QA / storage |

## 背景

真实辩论门禁中，实时行情、新闻和行业采集同时失败，但系统仍执行 16 次 LLM
调用并返回结构完整的结果。用户无法从结果页判断输入证据已断链。旧 `DataSource`
还使用 `[]` / `None` 同时表示真实空结果、接口不支持和网络失败，业务层无法做
可靠的完整性决策。

项目需要优先使用免费来源控制成本，同时必须保留未来增加、替换免费或付费接口的
能力。多个接口也可能共享同一个真实上游，因此“适配器数量”不能直接当作独立
证据数量。

## 决策

### 1. 核心证据不允许自动降级

实时行情、K 线、新闻和行业等当前业务链必需证据必须完整。任一类别未达到策略
门槛时，在启动昂贵 LLM 链前失败关闭；该次任务的 LLM 调用数必须为零。

### 2. 来源身份分为两层

每个适配器必须声明：

- `source_id`：项目中的具体接入实现；
- `upstream_id`：真实提供事实的机构；
- `capabilities`：明确支持的证据类别；
- `discovery_only`：是否仅用于发现线索。

完整性按去重后的 `upstream_id` 计算。多个适配器包装同一家媒体仍然只算一个
独立来源。发现型来源不参与证据门槛。

### 3. 查询结果采用六态契约

所有新来源返回：

- `SUCCESS_DATA`
- `SUCCESS_EMPTY`
- `FAILED`
- `UNSUPPORTED`
- `STALE`
- `CONFLICTED`

`SUCCESS_EMPTY` 只表示上游成功完成查询并明确返回零条。网络失败、解析失败、
权限不足和包装层异常绝不能伪装为空结果。

### 4. 业务层只依赖统一接口

具体来源通过 `EvidenceSourceRegistry` 注册，由 `DataEvidenceService` 并发调度、
格式化和执行完整性策略，再输出统一 `EvidenceEnvelope`。新增或替换来源只增加
适配器与配置，不修改辩论引擎和 Agent 业务逻辑。

### 5. 低成本优先，但完整性标准不降低

首期优先评估 CNINFO、东方财富、新浪/财联社、GDELT 和自建 RSSHub。RSSHub 仅作
发现源。Tushare 等付费接口保留扩展位，是否购买由真实覆盖率和失败率决定。

### 6. 盘中 AI 采用双时间尺度，不等待日 K 收盘

日 K 是否完成与盘中数据能否进入 AI 是两个不同问题。正式辩论的盘中输入必须拆成
以下四层，禁止把它们压成一条没有状态的数据序列：

1. **历史完整日 K（`FINAL_DAILY`）**：只包含已经收盘并通过多源核验的交易日，
   用于正式均线、趋势、支撑压力和日线形态；
2. **已结束分钟（`FINAL_MINUTE`）**：用于 VWAP、开盘区间和盘中量价事实；
3. **实时快照（`LIVE_QUOTE`）**：双源核验后的当前价格、成交量和行情时间；
4. **盘中动态状态（`PROVISIONAL`）**：正在形成的分钟和今日 OHLC，可以进入 AI
   供盘中判断，但必须携带采集时间、交易阶段和可变标识。

开盘后 AI 不等待收盘：它使用“上一交易日及以前的完整日 K + 今日实时行情 +
已结束分钟 + 明确标记的动态状态”。`PROVISIONAL` 不得混入 `FINAL_DAILY` 序列，
不得触发“已确认日线形态”或覆盖正式收盘指标。若展示含盘中估算的均线或指标，
必须与正式版本分字段、分标签输出。

当交易所收盘且多源确认当日最终 OHLC 后，当日数据才能从 `PROVISIONAL` 晋升为
`FINAL_DAILY`。历史日 K 或盘中必需证据缺失、陈旧、错时或冲突时，仍在首个 LLM
调用前失败关闭。

### 7. K 线以 RAW 事实对账，复权独立计算

K 线证据分为三个不可混淆的层：

1. `RAW`：上游返回的原始不复权 OHLCV/成交额，是跨源对账、订单价格核对和审计
   的事实底座；
2. `CORPORATE_ACTION`：分红、送转、配股、拆并股及复权因子，必须记录来源、
   除权日、基准日、版本和获取时间；
3. `ADJUSTED`：由项目统一算法基于指定 `as_of` 生成的派生序列，不是真实成交价。

完成日线只比较 RAW，不直接比较不同供应商的前复权成品价格。前复权供应商可能使用
不同基准日、分红再投资模型和舍入口径；这些差异应进入公司行动/因子诊断，不能误报
为 RAW 价格冲突。盘中技术分析使用点时前复权，历史回测只使用当时已经可获得的因子；
后复权只用于长期财富研究，不用于当前订单参考价。

发生股本变化时，复权成交量按价格因子的反方向调整；纯现金分红只调整价格。成交额
保留 RAW 口径。所有复权结果携带 `adjustment_mode`、`factor_source_ids`、
`factor_version`、`reference_date` 和 `as_of`。

### 8. 完成日线采用严格、精度驱动的冲突规则

行业规范没有规定一个通用的跨供应商百分比容差。项目按证券最小价位和来源声明精度
制定以下规则：

- 证券、市场、周期、交易日、币种和复权口径必须完全一致；
- RAW OHLC 按证券 `price_tick` 规范化后必须完全一致，差一个最小价位也返回
  `CONFLICTED / raw_ohlc_conflict`；
- 成交量统一为股。双方均为股精度时必须相等；若一方明确只有“手”精度，只允许
  小于一个来源精度单位的差异，并暴露 `volume_precision`；
- 成交额按来源声明的单位和精度规范化；精度未验证前只做诊断，不设置任意百分比；
- 日期集合在排除官方停牌后必须一致，不能靠缺行猜测停牌；
- 收盘晋升同时依赖交易阶段结束、双源同日、字段对账通过和状态稳定，不能只看墙钟。

实时快照的 `0.01 元` 容差和 L1 分时累计量的 `500 股` 经验容差属于不同数据时态，
不得用于完成日线。完整规则和分批实施顺序见
[K 线证据完整性实施计划](../02-requirements/KLINE_EVIDENCE_IMPLEMENTATION_PLAN.md)。

### 9. Phase R 来源边界

- 沪深 RAW 日线首期使用新浪直连与腾讯直连，按两个不同 `upstream_id` 计数；
- 同一东方财富上游的 AKShare、AData 或直连接口不能重复计数；
- 北交所在可靠第二上游验证完成前返回
  `INCOMPLETE / independent_upstream_missing`，不得伪造双源完成；
- 免费公开端点是低成本阶段方案，不等同于机构级数据保障。接口必须允许未来替换为
  交易所授权/持牌主源和独立校验源。

## 明确不做

- 不把同一上游的多个包装器算成多源；
- 不用异常文本猜测“真实零数据”；
- 不因免费来源失败而让 LLM 自动基于残缺证据继续；
- 不让具体来源名称泄漏到辩论引擎和 Agent；
- 不在来源语义未通过真实烟测前接入正式失败关闭链。
- 不把未收盘的今日动态 OHLC 伪装成完整日 K；
- 不因排除未完成日 K 而排除实时行情或要求用户等到收盘。
- 不用任意百分比掩盖完成日线 RAW 价格冲突；
- 不把不同供应商的前复权成品价格直接当作 RAW 对账对象；
- 不让回测读取历史时点之后才发布或修订的复权因子；
- 不让交易计划使用前复权或后复权价格作为订单参考价。

## 决策确认

用户于 2026-07-28 确认：

- 数据源必须存在多家来源并汇总为统一格式；
- 最新信息与数据库比对，已存在的不重复入库；
- 实时行情、K 线、新闻和行业证据均不能自动降级；
- PostgreSQL 可以替代 SQLite；
- 当前不在付费接口投入过多，但接口必须保留多样性和可替换性。

用户于 2026-07-30 进一步确认：

- 盘中 AI 不能因为当天日 K 尚未收盘而停摆；
- 历史完整日 K 与今日实时/分时证据必须同时进入业务上下文，但状态严格分离；
- 今日动态 OHLC 可以供 AI 使用，必须标记 `PROVISIONAL`，不得冒充收盘定论。
- 双源必须是两个独立上游，同一上游的包装器或传输双路不能重复计数；
- 完成日线以 RAW 严格对账，复权因子和派生序列独立保存并由项目统一计算；
- 完成日线 OHLC 按证券最小价位规范化后必须一致，不采用任意百分比容差；
- 沪深首期使用新浪 + 腾讯；北交所缺可靠第二源时明确失败关闭；
- 以上规则按跨部门实施计划分批落地，保持旧功能平稳迁移。
