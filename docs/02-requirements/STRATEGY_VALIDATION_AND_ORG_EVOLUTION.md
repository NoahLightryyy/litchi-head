# 投资有效性优先与组织演进战略设计

> **状态**：用户已批准；按原子任务分别制定实施计划，物理迁移仍需单独批准
> **日期**：2026-08-07  
> **范围**：产品定位、投资有效性验证、组织归属和慢迁移纪律  
> **不在本轮范围**：代码搬迁、目录重排、功能删除、评测平台建设

## 1. 战略背景

litchi-head 已经具备多 Agent 辩论、动态权重、反思、风控、交易计划、回测、复盘和
多源证据等较完整的工程能力。当前最大的产品缺口不是功能数量，而是尚未用统一、可复现、
含成本的比较证明：完整系统相对单 Agent、简单规则和买入持有产生了多少增量价值。

项目因此从“继续扩展架构”转向“先证明现有架构”。KR-3B-2 已完成，暂停新增 Agent、层级
和市场，把投资有效性验证与消融实验提升为最高 P0。稳定失败诊断和完整失败分母现已就绪，
下一步是规划 validation-first checkpoint，而非自动进入 KR-4。

## 2. 产品北极星

litchi-head 的核心产品定义调整为：

> 用可追溯证据、明确分歧、风险边界、置信度校准和历史可靠性，帮助用户进行投资研究与
> 决策；最终拍板和下单属于用户。

产品价值不再用“有多少层、多少大师、多少功能”衡量，而用相对简单替代方案的净增益衡量。
净增益同时包括预测质量、经济结果、安全性、运行质量和总成本。

大师人格保留为用户容易理解的表达层。底层逐步以可检查的策略原型描述能力，例如
`value`、`quality`、`growth`、`momentum`、`macro`、`event_driven`、`contrarian` 和
`statistical`。系统不宣称模拟真实人物本人。

## 3. 四条共同战略方针

1. **证据先于扩张**：新增复杂度前必须声明准备改善的指标、验证方法和失败后的处置。
2. **比较产生价值**：功能存在和测试通过只证明功能账，不证明投资效果账。
3. **简单替代优先**：完整系统必须同时面对现金/不行动、买入持有、简单规则和单 Agent。
4. **人负责拍板**：系统输出研究证据、情景和风险，不把未验证结论包装成确定性荐股。

## 4. 最小验证闭环

项目不建设新的大型模型治理平台。首轮只复用现有能力：

- `src/backtest/` 已有 Sharpe、最大回撤、胜率、盈亏比和 CAGR；
- `src/debate/trust.py` 已有 Brier score 和 calibration curve；
- `src/retro/` 已有推荐与实际结果记录；
- K 线证据链正在提供点时、版本化、可回放的数据；
- `python scripts/check.py --full` 已提供软件质量闸门。

首轮最小闭环只包含：

1. 冻结一批 `DecisionSnapshot`；
2. 同场运行完整版、单 Agent、简单规则和买入持有；
3. 统一计算预测、经济、安全、运行和成本指标；
4. 对主要层级进行单变量消融；
5. 产出一张含样本量、置信区间、失败分母和限制说明的比较表；
6. 根据证据决定保留、简化、关闭或复验。

评测协议继续以
[DECISION_BASELINE_AND_SHADOW_VALIDATION.md](DECISION_BASELINE_AND_SHADOW_VALIDATION.md)
为唯一指标口径事实源。本设计只改变其优先级、治理方式和启动顺序，不复制第二套指标定义。

## 5. 轻量治理模型

采用“中央定方向、统一协议裁判、部门自主作战”，但不建立常设委员会或审批系统。

### 5.1 中央只决定

- 产品北极星和对外承诺；
- 正式主 baseline、样本范围、成本口径和转段标准；
- 与资金、仓位、停止线、生产数据源和合规定位有关的决定；
- 是否根据最终证据删除具有明显产品影响的核心能力。

### 5.2 能力域自主决定

- 模块内部算法、代码结构和技术实现；
- 不改变冻结口径的探索性实验；
- 降低成本、延迟和运维复杂度的方法；
- 提出合并、关闭或替换自身能力；
- 对异常结果提出一次有明确理由的预注册复验。

### 5.3 统一协议负责裁判

- 回测研究维护统一计算口径、baseline 编排和配对比较；
- 投资效果验证检查数据泄漏、删样、版本漂移和统计复现；
- 各业务能力域不能自行更换正式样本、指标、成本或结果分母；
- 消融首次失败先检查样本量、市场状态和实现缺陷；有理由时允许一次预注册复验；复验仍无
  增益时默认关闭或移出核心链路。

这里的“裁判”是冻结配置、可重复命令和报告，不是新增管理层。

## 6. 组织现状审计

当前 11 个平级部门能够覆盖功能范围，但已经出现以下问题：

- 部门文档共 47 个 Markdown、约 5350 行，多数 `ROLE.md` 自 2026-06-21 后未更新；
- `src/callback/` 和 `src/retro/` 有实际业务，却没有清晰部门归属；
- AI Agent、辩论和记忆同时拥有“大师人格/角色”相关职责；
- 基础设施与 QA 对测试配置、CI 和运行环境存在交叉；
- 数据部旧“静默降级”规则与当前正式证据失败关闭相冲突；
- 基础设施旧多 Provider 描述与当前 DeepSeek 单 Provider 策略不一致；
- 风控、交易和 AI Agent 具有专业边界，但当前规模不足以承担完整平级部门治理成本。

因此组织覆盖基本完整，但边界已经不够经济，也存在规则漂移和无人归属。

## 7. 七个能力域

本设计把当前 11 个平级部门逻辑收敛为七个能力域。第一阶段只改变治理归属，代码和文档路径
保持原位。

| 能力域 | 当前代码/职责范围 | 结论 |
|:-------|:------------------|:-----|
| 数据与证据 | `src/data/` | 独立保留；拥有最大数据资产和最高完整性风险 |
| 决策智能 | `src/agents/`、`src/core/`、`src/debate/` | 合并 Agent 架构与辩论；Agent 是决策系统的能力组件 |
| 记忆与反馈 | `src/memory/`、`src/callback/`、`src/retro/` | 重组并补齐 callback/retro 的归属 |
| 风险与执行模拟 | `src/risk/`、`src/trader/` | 组织合并；风控与交易代码、红线继续隔离 |
| 评测研究 | `src/backtest/`、投资效果验证 | 强化 baseline、消融、统计和复现职责 |
| 产品交付 | `backend/`、`frontend/` | 后端和前端作为专业子组，共同对用户可见结果负责 |
| 平台运行 | `src/utils/`、CI、软件质量 | 合并运行基础设施和软件质量闸门 |

`00-cross-cutting` 改为战略事实源，不再视为生产部门。原质量保障职责拆分：软件 CI 和构建
归平台运行；投资实验的防泄漏、复现和统计验收归评测研究。

## 8. 责任守恒映射

组织合并不能造成业务丢失。第一阶段必须保留以下映射：

| 现有职责 | 新归属 |
|:---------|:-------|
| Agent 基类、通信协议、MasterAgent、辩论、评审、权重、置信度 | 决策智能 |
| 大师人格和策略原型定义 | 决策智能主责；记忆与反馈保存版本 |
| MemoryStore、知识库、CallbackEngine、M3-EXT、Retro Board | 记忆与反馈 |
| 风控辩论、确定性硬门禁 | 风险与执行模拟的风控子组 |
| TradePlan、执行步骤和成交模拟 | 风险与执行模拟的交易子组 |
| Backtest、baseline、walk-forward、消融和统计报告 | 评测研究 |
| API、持久任务、界面和四态展示 | 产品交付的后端/前端子组 |
| LLM、配置、成本、日志、CI、构建和软件测试闸门 | 平台运行 |
| 所有开放技术债务 | 随职责映射；原 ID、历史和状态保持不变 |

每项职责必须有且只有一个主责能力域，可以有配合方，但不能无人负责或多头裁决。

## 9. 业务不丢失的五项验收

1. **功能守恒**：现有入口、行为和输出不因组织调整而改变。
2. **接口守恒**：所有提供方和消费者仍有明确负责人。
3. **债务守恒**：每个开放 TD 都有唯一新归属，不丢失、不复制新 ID。
4. **规则守恒**：有效红线全部进入新归属；过时规则显式修订，不能静默消失。
5. **证据守恒**：测试、日志、ADR、学习卡片和历史交接继续可追溯。

反向检查同样必须执行：每个新能力域声明的职责必须能指向现有代码、文档或明确批准的战略
任务，不能凭空创造组织故事。

## 10. 组织存在价值评判标准

每个候选独立能力域按七项评估，每项 0～2 分：

1. 是否有不可被相邻组织自然吸收的独立结果责任；
2. 是否拥有明确代码、数据、协议或运行资产；
3. 是否经常需要独立的专业判断；
4. 是否承担必须相互制衡的资金、安全或验证风险；
5. 是否通过稳定契约服务多个上下游；
6. 是否有自己的长期 backlog 和演进节奏；
7. 分离减少的认知负担是否大于文档、同步和协调成本。

解释区间：

- 10～14：适合独立能力域；
- 6～9：作为专业子组；
- 0～5：合并或删除；
- 安全制衡可以覆盖分数，但必须指出具体风险和隔离机制。

满足以下任意两项时触发合并审查：连续两个阶段无独立交付、80% 以上任务与另一组织共同
发生、没有独立消费者、职责可被相邻组织完整覆盖、文档持续与代码或战略不一致、无法定义
自身价值指标。

该检查只在 Phase 转段、准备新增组织或出现明显职责冲突时进行，不新增固定周期会议。

## 11. 慢迁移纪律

大动作搬家必须慢。采用四阶段、每阶段可独立停止的迁移方式：

### 阶段 O0：冻结与映射

只建立当前组织、职责、接口、债务和规则清单，不改路径。

### 阶段 O1：逻辑归属

只更新组织总览和战略事实源；旧部门目录保留，标记为七个能力域下的专业子组或历史责任
入口。现有代码、API、模型、测试和债务不动。

### 阶段 O2：运行观察

至少运行一个完整阶段，观察新归属是否减少重复加载、文档漂移和多头决策。如果没有明确
收益，停止迁移并保留现有物理结构。

### 阶段 O3：可选物理整理

只有在 O2 证明物理结构仍造成持续成本时，才单独提出迁移设计。实施前必须具备：完整引用
清单、逐文件去向、自动化引用检查、全量测试、明确回滚点和用户再次批准。

任何阶段都不得以“组织合并”为理由顺便删除业务功能或改变产品行为。

## 12. 执行顺序

1. 确认 KR-3B-2 的稳定失败分类和完整分母已作为正式实验前置条件；
2. 执行 O0 责任守恒清点；
3. 执行 O1 逻辑归属，不搬代码和目录；
4. ✅ 已批准 [E0-100 validation-first 设计](../superpowers/specs/2026-08-10-e0-validation-checkpoint-design.md)，TD-074 改为 E0 离线证伪 → KR-4～6 → E1 影子验证；
5. 建立最小 DecisionSnapshot、四组 baseline 和单张结果表；
6. 先回答完整版是否优于简单替代，再决定 KR-4～6 的范围；
7. 一个阶段后审查 O2，物理迁移仍需新的用户决策。

## 13. 明确不做

- 不新增部门、常设委员会或审批服务；
- 不立即重排 `src/`、`backend/`、`frontend/` 或部门文档目录；
- 不为首轮实验建设通用模型治理平台；
- 不在第一张可信比较表之前扩大师、扩层或扩市场；
- 不用组织调整掩盖 TD-061、TD-067、TD-072、TD-074 等真实债务；
- 不把小样本、回测或功能测试宣传成真实投资效果已经得到证明。

## 14. 设计验收标准

后续实施计划必须证明：

- 七个能力域覆盖全部现有职责、接口和开放债务；
- 新结构没有新增代码迁移或运行时依赖；
- TD-074 仍是唯一评测口径事实源；
- 首轮实验能复用现有回测、校准、复盘和 K 线证据能力；
- 部门自治不包括修改冻结实验口径；
- 物理迁移必须经过 O2 观察和单独批准；
- 项目能在最短路径上产出第一张可信对比表，而不是新增另一座工程大山。

### A. API模型能力实验与公开评测

产品问题：同一个模型，经过更好的证据检索、计算工具、任务拆分和核验，能增加多少可复现的研究价值？

实验梯子：直接问答 → 点时证据检索与引用 → 确定性计算工具 → 计划/执行/核验 → 有预算限制的多轮研究与反证 → 多Agent辩论。每次只增加一项；失败案例分类后针对性优化，在独立保留集验证。结构化输出、工具参数校验、缺证拒答、上下文筛选、任务路由和缓存也纳入实验，不以更多token或更多Agent作为能力提升证据。首轮使用现有模型与现有凭据；新增付费模型和支出上限另行确定。

两类比较分开：同一模型比较工作流；同一工作流比较模型。除固定token/调用预算对照外，另做固定金额对照，保存模型版本、推理档位、工具、数据快照、成本与延迟。API公开能力是边界，不假设能获取内部思考过程或修改模型权重。

| 独立榜单 | 可检验维度 | 必须一起展示 |
|---|---|---|
| 证据与财务能力 | 数值计算正确率、引用支持率、信息时效、事实错误率 | 数据集版本、人工复核及评分规则 |
| 概率预测 | Brier、校准、分周期方向表现 | 样本量、覆盖率、拒答率、基准 |
| 投资效果 | 成本后收益、相对基准超额、回撤、风险调整收益 | 同期风险暴露、换手、不可成交与失败样本 |
| 可靠性与效率 | 完成率、约束违规、工具失败恢复、P95延迟、单次研究成本 | 调用预算、超时与错误分母 |
| 资金适配 | 不同本金下可执行率、费用占比、集中风险与现金需求满足度 | 相同目标/风险约束，不同资金赛道 |

不得把这些分数任意相加包装成唯一“最聪明模型”。先展示分榜和成本/质量权衡；综合权重如有需要，先冻结。样本不足、差异无法区分时标记暂不排名/并列。置信区间须考虑收益序列与同日样本相关性，不把每只股票当独立重复实验。

股市收益衡量整套系统，受行情、仓位和执行影响；知识准确、政策理解也必须独立测量。沿用DECISION_BASELINE_AND_SHADOW_VALIDATION.md的唯一正式协议，包含现金、指数、等权、简单策略、单Agent对照。只使用当时可见信息；事前冻结股票池、时间窗、成本、停止条件，记录所有失败。历史回放可能被模型预训练污染，因此另设前瞻模拟交易赛道，不以纸面成绩声称实盘获利。

公开评测的产品传播路径：先复现一个外部协议，再公布可复现报告和本项目影子成绩；只有主办方确认收录后才写“官方上榜”。美股历史榜与A股实时模拟榜不同表，不能直接比较名次。核验报名机制、许可证、数据发布权、最近更新和复现成本后再选目标；当前没有证据宣称哪一个是“最热门”。

截至2026-10-18核验候选：
- [StockBench](https://stockbench.github.io/)：有收益、回撤和Sortino榜；页面实验为2025年美股窗口，适合作为协议复现候选，不能称当天实盘榜。
- [FinBen论文](https://arxiv.org/abs/2402.12659)：覆盖多类金融任务，适合检验金融能力，不能替代投资效果验证。
- [LiveTradeBench论文](https://arxiv.org/abs/2511.03628)：动态交易评测候选；接入和提交资格尚未核验。

### B. 央视政策战略研究栏目

入口提案：“政策与国家战略”。从[央视新闻/新闻联播](https://tv.cctv.com/lm/xwlb/)及[经济信息联播](https://tv.cctv.com/lm/jjxxll/index.shtml)的公开报道入手，回溯国务院、部委及正式政策文件原文。栏目页已发现不等于采集接口、授权及完整覆盖已经核验。

每张研究卡保留：报道标题/发布日期/原文链接、政策原文与发布机构、事实摘要、相对既有政策的变化、落地阶段、产业传导路径、潜在受益与成本承担方、观察指标、兑现期限、反证与失效条件。明确分开官方原文事实与本产品AI推断，推断标注证据强弱及未知项，不能暗示央视背书。

“战略方向 → 政策工具 → 预算/标准/采购等落地证据 → 产业需求/成本 → 企业披露”逐级核验。没有公司级证据时只到行业，不能因为新闻提到行业就生成确定性买入结论。重复报道按事件去重，政策修订保留时间线；记录首次可见时间，避免事后材料进入旧预测。

验收分两层：人工检查政策原意、引用与传导依据；再用预先定义的行业/经营指标观察兑现。即时股价反应与长期战略兑现分开统计。内容形态以摘要、必要短引与原文跳转为主，采集方式和再发布范围在接入前核验。

### C. 本金与约束驱动的策略规划

产品问题：同一条研究结论，在不同资金和现金需求下是否可执行、是否值得执行？本金不是风险偏好的替代变量。

输入提案：币种、可投资本金、需保留的生活/应急资金、近期用款、负债、稳定收入/追加资金、持有期限、可承受亏损、经验、市场权限及现有持仓。用户未提供时展示情景分析，不能猜测真实资金或给出默认实盘比例。

研究用情景可先设1万、10万、50万元人民币，以同一风险/期限条件比较（仅产品测试输入，不是推荐档位）：
- 资金较小：检验最低交易单位、费用侵蚀、单一持仓集中度以及ETF可行性。
- 资金增加：检验分散化、再平衡、研究/API费用是否仍划算。
- 更大本金：检验流动性、冲击成本、相关性和现金调度；不能据金额自动升级杠杆或复杂产品。

输出包括可执行候选方案、为何适合这些约束、预计研究成本、交易成本假设、压力情景、再平衡条件与“不行动”选项。模型提出备选，确定性规则验证金额、交易单位、权限及风险约束；数值默认值和正式配置需另行确认。真实净收益展示需同时列交易费用和模型/API费用，避免小本金账户被固定成本吞噬。

### 差异化闭环与建议验证顺序

产品定位提案：面向个人资金约束、能够解释政策依据并公开验证自身有效性的AI投资研究助手。

同花顺已有[自然语言问财及策略能力](https://search.10jqka.com.cn/skillhub)，所以“AI问答/新闻摘要/资产配置”本身不足以建立差异。竞争假设是让用户看到：本次结论基于什么、此前同类判断表现如何、当前本金是否执行得起。该假设仍需用户访谈和任务对照验证，不能宣称竞品没有这些能力。

建议先后：冻结一个小范围的评测/成本协议；人工选取政策事件形成可核验研究卡；用本金情景验证同一研究结果的可执行差异；积累前瞻记录后再开发公开榜单和对外传播。先解决数据可靠性前置问题，不直接重排当前实现任务。独立App化属于交付形态，与这三条研究价值主线分别推进。

首个可评审产物：一份候选评测协议、一组政策卡样例、一张多本金情景对照表。评测预算、正式资金档位、风险阈值和数据接入契约尚未冻结。此次仅更新产品方向，不触发付费评测、自动交易或外部榜单提交。
