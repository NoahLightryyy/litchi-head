# 决策 Baseline 与影子验证计划

> **状态**：战略方向已确认；具体基准标的、交易成本和转段阈值仍须在实现前由用户确认。
> **唯一事实源**：本文是“AI 是否真的比简单方法更有用”的跨部门验收标准。
> **当前顺序**：先完成 K 线证据链 KR-2～KR-6，再进入影子验证；不得用本计划打断当前数据主线。

---

## 1. 为什么必须有 baseline

项目当前最主要的矛盾不是“功能不够多”，而是：

> **系统建设能力很强，但真实结果验证能力很弱。**

没有 baseline，AI 的每次成功都可以被解释成“模型很聪明”，每次失败又可以被解释成
“市场特殊”。这不能证伪，也不能判断多 Agent、辩论、校准和风控究竟带来了增量价值。

因此必须把两本账分开：

| 账本 | 回答的问题 | 当前状态 |
|:-----|:-----------|:--------:|
| 功能账 | 模块是否存在、接口是否可用、测试是否通过 | 较强 |
| 证据账 | 相对简单基线是否产生稳定、可重复、成本后仍存在的增量价值 | 尚未建立 |

README、看板和前端不得再用“有置信度字段”“有复盘页面”代替“置信度已完成校准”
或“投资效果已得到验证”。

## 2. 验证对象

验证单位不是一句自然语言，而是一条冻结的 `DecisionSnapshot`。每条样本至少保存：

- `decision_id`、股票代码、决策时间、交易日和市场状态；
- 模型、Prompt、代码提交、配置和策略版本；
- `snapshot_id`、数据来源、`as_of`、RAW/复权坐标和完整性状态；
- AI 方向、目标周期、置信度、建议入场/止损/止盈和拒绝原因；
- 同时刻各 baseline 的方向与仓位；
- 后续 1/5/20 个交易日的统一结果标签；
- 交易成本、滑点、停牌/涨跌停等不可成交事实；
- 用户是否采纳及实际操作——单独记录，不得与模型能力指标混为一谈。

未形成上述快照的历史聊天或人工回忆，不进入正式效果统计。

## 3. Baseline 梯子

最终参数需要单独确认，但每次正式实验至少保留下列五类对照：

| ID | 基线 | 作用 |
|:--:|:-----|:-----|
| B0 | 不行动/现金 | 检查 AI 是否因过度交易制造损失；也是安全基线 |
| B1 | 对应市场或股票池指数 | 判断是否仅仅吃到了市场方向 |
| B2 | 股票池等权买入持有 | 判断选股/择时是否优于最简单暴露 |
| B3 | 冻结参数的简单规则 | 如单一均线或动量规则；检验复杂系统是否优于低成本规则 |
| B4 | AI 消融基线 | 单 Agent、无辩论或无校准版本；隔离多 Agent 组件的真实贡献 |

规则：

1. 同一批样本、同一决策时间、同一价格坐标、同一成本假设；
2. 基线参数必须在实验前冻结，不能看完结果再挑最好的一条；
3. 主 baseline 只能有一个，其他作为辅助解释；主基准标的须按股票池预先确认；
4. baseline 失败或数据缺失也必须入账，不能只保存 AI 的完整样本；
5. B4 只用于回答架构增量，不代替市场/简单策略对照。

## 4. 影子验证协议

### 4.1 预注册

每轮开始前冻结：

- 股票池及纳入/剔除规则；
- 固定触发时间和每日最大样本数；
- 1/5/20 日标签定义及中性区间；
- 主 baseline、辅助 baseline 和版本；
- 手续费、印花税、滑点及不可成交处理；
- 成功、失败、停止和延长条件；
- 代码提交、模型版本和 Prompt 版本。

任何中途变更都开启新实验版本，不能覆盖旧版本。

### 4.2 执行

1. 在固定时间同时生成 AI 与 baseline 决策；
2. 先写入不可变决策账本，再向用户展示；
3. 数据不完整时记录 `ABSTAIN` 或失败原因，不补算、不回填当时不可见的信息；
4. 到期后由系统按点时 RAW/复权规则自动生成结果标签；
5. 统计程序只读冻结快照，不调用当前模型“重新解释”过去；
6. 每周形成一次含全部分母和失败样本的报告。

### 4.3 样本阶段

以下是待用户确认的建议门槛，不是已经批准的实盘阈值：

| 阶段 | 建议最低样本 | 能回答什么 | 不能回答什么 |
|:----:|:-----------:|:-----------|:-------------|
| S0 冒烟 | 20 | 链路、标签和统计是否正确 | 不能声称策略有效 |
| S1 初步 | 100 | 发现明显失效、过度自信和运行问题 | 不能代表不同市场状态 |
| S2 内部证据 | 300+，覆盖上涨/下跌/震荡 | 初步比较增量价值和校准 | 仍不能承诺未来收益 |

时间建议至少连续 4～8 周；样本量和市场状态覆盖必须同时满足，不能用同一天大量相似
股票凑够分母。

## 5. 四类指标

### 5.1 预测质量

- 方向准确率、平衡准确率；
- Brier Score、校准曲线和 ECE；
- 按置信度分桶后的真实正确率；
- 按 1/5/20 日、行业和市场状态分层；
- 样本量和置信区间。

### 5.2 经济结果

- 扣除成本后的累计收益和相对主 baseline 的超额收益；
- 年化收益、Sharpe、最大回撤、盈亏比和换手率；
- 每笔决策的配对差值，而不只比较两条独立总收益曲线；
- 不可成交、停牌和涨跌停造成的执行偏差。

### 5.3 安全与拒答

- `ABSTAIN` 覆盖率；
- 已给建议样本的选择性风险；
- 数据冲突、陈旧、缺源时的正确拦截率；
- 高置信度错误率和最坏单笔/连续损失；
- 越过硬门禁的次数——目标必须为零。

### 5.4 运行质量

- 每次决策耗时、费用和失败率；
- 服务重启后的任务恢复率；
- 数据源故障、模型超时和前端离线的可见性；
- 决策快照、结果标签和统计报告的可重复生成率。

不能只汇报收益；如果收益来自不可接受的回撤、未来信息、不可成交价格或选择性删样，
该结果无效。

## 6. 防自欺纪律

以下行为会使整轮实验失效：

1. 事后更换基线、时间窗、中性区间或成本；
2. 删除失败、拒答、停牌或表现差的样本；
3. 用今天的数据、复权因子或模型重算过去决策；
4. 同时试大量参数，只展示最好的一组；
5. 把用户没有采纳 AI 的结果算成 AI 成功，或反过来；
6. 用“准确率高”掩盖亏损，用“收益高”掩盖极端回撤；
7. 在样本不足时把置信度称为经验证概率；
8. 由同一实现同时生成决策、定义标签并独占验收。

正式报告必须同时展示分母、失败样本、版本、时间窗和限制。

## 7. 部门责任

| 部门 | 必须交付 |
|:-----|:---------|
| 数据管道 | 点时行情、公司行动、统一复权、基准数据和到期标签；不增加未经确认的数据源 |
| 辩论引擎 | 冻结 AI 决策与置信度；提供单 Agent/无辩论等消融入口 |
| AI Agent | Prompt/模型/知识版本可追溯；样本不足时不得把 confidence 表述为概率 |
| 记忆系统 | 不可变决策账本、实验版本和结果事件；原始记录不得被学习回写覆盖 |
| 风控 | 把数据完整性、仓位、相关暴露和回撤停止线做成确定性门禁 |
| 交易执行 | 统一 RAW 成交坐标、费用、滑点和不可成交规则；影子阶段不得自动下单 |
| 回测研究 | baseline 编排、配对比较、walk-forward、置信区间和分层报告 |
| 后端 API | 持久任务、结果回填和实验/report API；进程重启后可恢复 |
| 前端 | 区分功能完成度与证据成熟度；展示样本量、基线、区间、失败与限制 |
| 基础设施 | 模型/配置/提交版本、成本、运行健康、备份恢复与一键启动 |
| 质量保障 | 无绕过生产 E2E、故障注入、统计复现和反作弊验收 |
| 跨部门治理 | 冻结实验口径、审查改动、维护停止线并发布周报 |

## 8. 阶段顺序

### 战役 A：生产链封口

完成 KR-2～KR-6。验收核心是：生产路径无证据门绕过，缺失/冲突数据不进入 LLM，
价格坐标可追溯，API/前端可见，回测无未来信息。

### 战役 B：影子验证

冻结 baseline 协议并连续积累 S0→S1→S2 样本。此阶段可以给用户看建议，但默认不自动
下单，不以少量胜负改模型。

### 战役 C：小规模风险受限试用

只有在用户确认量化阈值、S2 报告通过、运行恢复和硬风控通过后才讨论。初始资金上限、
单笔仓位、回撤停止线属于跟钱相关的默认值，必须另行确认。

## 9. 当前停止线

在完成相应证据前：

- 不宣称“帮你盈利”或“一流实盘产品”；
- 不把启发式/小样本置信度称为真实成功概率；
- 不因功能测试通过而扩大真钱规模；
- 不允许自动下单；
- 不用新增 Agent、指标或市场替代 baseline 闭环；
- 对外公开、收费或向不特定用户提供建议前，必须另做合规审查。

## 10. 转段与改判条件

从“建设期”进入“证据期”，必须同时满足：

1. KR-2～KR-6 生产链验收通过；
2. 决策、基线和结果能不可变留痕；
3. 主 baseline、成本、标签和停止线得到用户确认；
4. 真实生产 E2E 不绕过数据/风控门禁；
5. 报告能从冻结数据重复生成。

当前判断成立的前提是项目尚无大规模、时间戳冻结、样本外、含成本的真实结果集。若已经
存在满足上述协议的 100+ 连续样本、可靠生产恢复证明或浏览器级 E2E，应重新核对并调整
成熟度判断，不得为维护既有结论而忽略反证。
