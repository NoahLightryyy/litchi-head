# K 线证据完整性实施计划

> 状态：产品方向与风险口径已批准，代码尚未实现
>
> 决策源：[ADR-013 多源证据完整性](../05-decisions/ADR-013-multi-source-evidence.md)
>
> 主债务：`TD-069`
>
> 目标：让盘中 AI 持续工作，同时保证完成日线、动态行情和复权结果不混淆、不静默降级。

## 1. 为什么必须分批实施

K 线门禁会同时影响数据采集、复权、指标、AI 上下文、风控、回测、API 和前端。
一次性替换所有旧链路会放大回归风险。因此本计划采用“先建立事实底座，再逐层切换
消费者”的顺序；每一批都必须保持旧功能可运行，并通过本批验收后才能进入下一批。

本文件负责实施顺序和部门交接；不可违反的业务规则以 ADR-013 为唯一事实源。部门
文档只写各自职责并引用 ADR-013，不自行发明来源、阈值或复权算法。

## 2. 不可违反的统一规则

1. 双源按不同 `upstream_id` 计算。同一机构的不同包装器、SDK、A/B 传输线路只算
   一个事实源。
2. 原始不复权 `RAW` 日线是不可变事实底座；公司行动/复权因子与复权结果分层保存。
3. 完成日线的证券、市场、周期、交易日、币种和复权口径必须完全一致。
4. 完成日线 RAW OHLC 按证券 `price_tick` 规范化后必须完全一致；差一个最小价位
   也进入 `CONFLICTED`。实时行情和分钟战况的经验容差不得套用到完成日线。
5. 成交量统一为“股”。双方均为股精度时要求完全一致；若一方明确只有“手”精度，
   只允许小于一个来源精度单位的差异，并必须暴露精度限制。
6. 成交额按来源声明的单位和精度规范化。在来源精度没有被验证前只做诊断，不用
   任意百分比决定完整性。
7. 前复权成品价格不做跨供应商直接阈值比较。系统先核验 RAW，再核验公司行动、
   基准日和因子，最后由统一算法生成复权序列。
8. 盘中 AI 使用 `FINAL_DAILY + FINAL_MINUTE + LIVE_QUOTE + PROVISIONAL`，不等待
   当日日线收盘；`PROVISIONAL` 永远不能冒充收盘定论。
9. 历史回测只能使用当时已经可获得的点时复权信息，不得用今天的因子改写历史认知。
10. 任一必需层缺失、陈旧、语义不明或冲突时，在首个 LLM 调用前失败关闭，并向用户
    显示具体原因；不得静默选择一个来源继续。

## 3. 来源方案与边界

| 市场 | Phase R 免费阶段 | 完整性结论 | 后续目标 |
|:--|:--|:--|:--|
| 沪深 | 新浪直连 RAW 日线 + 腾讯直连 RAW 日线 | 两个独立上游；进入 TDD 实现 | 交易所授权/持牌主源 + 独立校验源 |
| 北交所 | 新浪已验证；腾讯历史日线未形成可靠第二源 | 第二上游就绪前返回 `INCOMPLETE` | 验证东方财富直连或接入持牌来源 |

`AKShare → 东方财富`、`AData → 东方财富` 和东方财富直连不能算三个来源。来源矩阵
必须记录 `source_id`、`upstream_id`、市场覆盖、字段单位、字段精度、复权语义和
最近烟测时间。

免费公开端点属于 Phase R 的低成本工程方案，不等同于机构级数据保障。系统必须
保留替换为交易所授权或付费来源的接口，不能把供应商名称写进辩论、Agent 或前端
业务逻辑。

## 4. 数据分层和用途

| 层 | 保存内容 | 允许用途 | 禁止用途 |
|:--|:--|:--|:--|
| `RAW` | 原始不复权 OHLCV/成交额、单位、精度、来源时间 | 审计、跨源对账、订单价格核对 | 直接跨除权日计算长期指标 |
| `CORPORATE_ACTION` | 分红、送转、配股、拆并股、因子、基准日、版本 | 复权计算、事件核验 | 无版本覆盖旧因子 |
| `ADJUSTED_QFQ_ASOF` | 指定 `as_of` 基准日的点时前复权 | 盘中技术分析、点时回测 | 当作真实成交价 |
| `ADJUSTED_HFQ` | 后复权研究序列 | 长期财富和收益研究 | 当前下单价格、实时支撑位 |

发生股本变化时，复权成交量按价格因子的反方向调整；纯现金分红只调整价格。
成交额保留 RAW 口径。所有复权输出必须携带 `adjustment_mode`、`factor_source_ids`、
`factor_version`、`reference_date` 和 `as_of`。

## 5. 完成日线对账矩阵

| 检查项 | `complete=True` 条件 | 失败状态/原因 |
|:--|:--|:--|
| 来源独立性 | 至少两个不同 `upstream_id` | `INCOMPLETE / independent_upstream_missing` |
| 证券身份 | 代码、市场、币种一致 | `CONFLICTED / instrument_identity_conflict` |
| 日期集合 | 排除官方停牌后，完成交易日集合一致 | `STALE` 或 `CONFLICTED / trading_date_conflict` |
| RAW OHLC | 按 `price_tick` 规范化后逐字段相等 | `CONFLICTED / raw_ohlc_conflict` |
| RAW 成交量 | 统一为股；差异小于已声明的最低来源精度 | `CONFLICTED / raw_volume_conflict` |
| 成交额 | 单位与精度已知后按精度对账 | 未验证前记录诊断，不参与成功判定 |
| 公司行动 | 事件类型、除权日、基准日和因子版本可追溯 | `CONFLICTED / adjustment_conflict` |
| 今日动态条 | 保持独立 `PROVISIONAL` | 禁止追加到 `final_daily_bars` |

停牌不能靠“缺一行”猜测，必须使用交易日历/证券状态证据。收盘晋升不能只依赖墙钟；
必须同时满足交易阶段已结束、双源返回同一完成交易日、字段对账通过和数据状态稳定。

## 6. 分批实施顺序

### KR-0：规范冻结与引用清理

- ADR-013 固化统一规则；
- 本计划登记部门职责、依赖和验收；
- ROADMAP、全局交接、部门交接与债务统一引用；
- 搜索并区分实时行情 `0.01 元`、分钟累计量 `500 股` 和完成日线严格对账，禁止
  三种阈值互相引用。

**交付条件**：所有相关部门能从各自 HANDOVER 找到同一 ADR、主债务和下一步。

### KR-1：RAW 双源事实底座

#### KR-1A：双源采集与逐日严格对账（✅ 2026-07-30 完成）

- 先写 RED 契约：来源独立性、代码路由、单位/精度、交易日集合、停牌、缺日、
  OHLC 冲突、成交量精度和北交所缺第二源；
- 实现新浪/腾讯沪深 RAW 日线适配器和统一 `KlineEvidenceEnvelope`；
- 保留旧 `DataCollector.get_klines()` 兼容入口，不立即切换全部消费者。

**已交付**：

- `RawDailyBar` 固定 `RAW / CNY / 1d`、市场、最小价位、成交量/额精度；
- 新浪与腾讯声明不同 `upstream_id`；腾讯“手”统一为“股”并保留 100 股精度；
- 完成日线 OHLC 差一个最小价位即冲突，成交量按来源精度对账；
- 当日未完成动态条被排除，带时区窗口为必需输入；
- 沪深真实代表样本通过，北交所因腾讯第二上游缺失明确
  `INCOMPLETE / independent_upstream_missing`；
- 新证据链保持旁路，旧 `DataCollector.get_klines()` 未切换。

#### KR-1B：交易日完备性与审计持久化（🔥 下一原子功能）

- 接入经过批准的交易日历与个股停复牌状态证据，形成请求窗口的“预期完成交易日集”；
- 同时校验“每个来源是否覆盖预期日期”和“两个来源日期是否一致”，禁止两个来源
  同时漏同一天却误判为完整；
- RAW、逐源诊断、原始响应摘要、采集时间和来源版本按 ADR-012 持久化；
- 建立长时间窗分页/覆盖证明，禁止两个来源同时截断却误判为完整。

**KR-1 完整交付条件**：KR-1A 已通过；KR-1B 的官方日历/停牌证据、持久化、长窗
覆盖与回放通过后，才允许进入 KR-2。交易日历或证券状态属于新增数据源决策，未经
用户确认不得自行选源。

##### KR-1B 来源调研结论（2026-07-30）

| 候选 | 实测/文档证据 | 判定 |
|:--|:--|:--|
| 上交所、深交所、北交所年度休市公告 | 三家均发布 2026 年官方休市安排；北交所规则明确周一至周五、法定节假日和公告休市日休市 | **权威事实源**，按交易所和年度版本化保存 |
| 交易所停复牌页面/上市公司公告 | 上交所有结构化停复牌查询；深交所、北交所有交易所/公司停复牌公告 | **权威证据**，只允许有明确代码、起止时间和公告链接的全天停牌排除日期 |
| AKShare `tool_trade_date_hist_sina` | 2026-07-30 实测覆盖 1990-12-19～2026-12-31；真实上游为新浪 | 只作独立校验/发现，不冒充官方日历 |
| AKShare `stock_tfp_em` | 上游为东方财富；传入 `20260417` 实测返回 2026 年 7 月当前停复牌表，日期过滤语义漂移 | **不得参与完整性成功判定**；修复前仅作候选发现 |
| Tushare `trade_cal` / `suspend_d` | 提供统一接口，但交易日历文档只明确 SSE/SZSE；当前环境无包、无令牌，且需积分 | 可选持牌/账户型替代；配置令牌并完成 BSE 覆盖烟测前不得启用 |

**推荐的免费阶段默认方案（待用户确认）**：

1. 三家交易所年度休市公告生成按 `market + year + source_url + published_at +
   content_hash` 版本化的本地交易日历；三个市场分别保存，不因日期通常相同而合并
   身份；
2. 新浪交易日历只作差异告警，不能覆盖交易所版本；
3. 某个官方开市日若两家 K 线都缺失，只在交易所停复牌页面或上市公司官方公告
   明确证明该证券全天停牌时排除；无法取得权威证据即失败关闭；
4. 盘中临时停牌不等于整日无日线，不能从预期日线集合剔除；
5. 东方财富停复牌数据只能帮助定位候选公告，不能单独把缺日判成合法停牌；
6. 未来接入授权/付费供应商时实现同一端口，并保留官方公告抽样核验。

### KR-2：公司行动与统一复权

- 建立版本化公司行动/因子模型；
- 明确免费阶段的因子来源及独立事件核验来源；
- 实现统一前复权算法、成交量调整规则和点时 `as_of`；
- 验证除息、送转、配股、停牌跨日和因子修订；
- 不把不同供应商的前复权成品价直接当作 RAW 冲突。

**交付条件**：同一 RAW + 同一因子版本产生确定性结果；历史点时测试证明无未来信息。

### KR-3：双时间尺度业务信封

- 输出 `final_daily_bars`、`final_minute_bars`、`live_quote`、
  `provisional_session_bar`；
- 正式日线指标只消费 `FINAL_DAILY` 的统一前复权序列；
- 可选盘中估算指标使用独立字段和标签；
- 收盘晋升建立幂等状态机，失败可重试，不覆盖已审计 RAW。

**交付条件**：开盘后 AI 输入齐全且无需等待收盘；动态条无法混入完成日线。

### KR-4：辩论、Agent、风控和交易串联

- 辩论引擎在首个 LLM 前检查必需层；
- Agent 提示词和结构化输出保留数据状态、口径和 `as_of`；
- 风控把数据完整性作为独立硬门禁，不用降低置信度代替失败关闭；
- 交易计划的参考价必须来自 `LIVE_QUOTE/RAW`，禁止使用复权价下单；
- 结果记录证据版本，便于复盘。

**交付条件**：所有缺源、错源、冲突、复权冲突测试均证明 LLM/交易调用为零。

### KR-5：API 与前端迁移

- 新证据 API 分栏返回四层数据、复权元数据、逐源诊断和错误码；
- 旧 K 线展示接口保持兼容，前端切换完成后再评估废弃；
- 前端分别展示完成日线、盘中动态、数据时间、复权口径和证据状态；
- 北交所缺第二源、复权冲突和证据陈旧必须是用户可见状态。

**交付条件**：loading/error/empty/offline/data 五态和收盘晋升流程均通过浏览器验证。

### KR-6：回测、存储、监控和全链路验收

- 回测按 `as_of` 读取点时因子，建立未来信息防护；
- Parquet/数据库保存 RAW、公司行动、派生序列和版本血缘；
- 健康检查按市场/来源/能力展示覆盖、延迟、冲突率和最后成功时间；
- 质量保障运行跨部门契约、属性、回放、故障注入和真实烟测；
- 达到机构级来源前，产品界面保留免费来源风险提示。

**交付条件**：全量检查、前端构建、真实沪深样本、北交所失败路径和历史回放全部通过。

## 7. 部门责任和交接点

| 部门 | 主要责任 | 向下游交付 |
|:--|:--|:--|
| 数据管道 | 独立来源、RAW 对账、公司行动、复权、四层信封 | 版本化 Pydantic 契约与诊断 |
| 辩论引擎 | LLM 前完整性门禁、上下文分区 | 零 LLM 失败证据 |
| AI Agent | 状态化措辞、禁止把动态/复权价写成事实成交价 | 带口径与时间的结构化结论 |
| 记忆系统 | 保存结论所用证据版本，不跨版本误召回 | 可重放的证据引用 |
| 风控 | 数据完整性硬门禁和风险告警 | `passed=false` 与明确原因 |
| 交易执行 | 只用实时/RAW 参考价，拒绝复权价和不完整证据 | 可追溯交易计划 |
| 回测研究 | 点时复权、无未来因子、可重复数据快照 | 带数据版本的报告 |
| 后端 API | 分栏响应、稳定错误码、兼容迁移 | 前端可消费契约 |
| 前端 | 状态、时间、口径、冲突和风险可视化 | 用户可见的真实数据身份 |
| 基础设施 | 来源配置、健康指标、告警和密钥/限流 | 可观测运行环境 |
| 质量保障 | 契约矩阵、回放、故障注入、全链路闸门 | 独立验收报告 |

## 8. 平稳迁移和回滚原则

1. 新证据链先旁路运行并记录诊断，验证通过后再成为正式 AI 输入。
2. 旧页面接口在前端迁移完成前保持兼容；不得一次删除所有旧调用。
3. 新链路异常时允许回滚到“禁止启动 AI”，不允许回滚到“残缺数据继续分析”。
4. 每一批单独提交，包含代码、测试、文档、债务、引用清理和学习卡片。
5. 每批完成后执行 `python scripts/check.py --full`；未通过不得进入下一批。

## 9. 最终完成定义

- 沪深完成日线有两个独立 RAW 上游，北交所能力边界真实可见；
- RAW、公司行动和派生复权序列可以独立审计和重放；
- 完成日线、实时、分钟和动态状态无法在类型或字段上互相冒充；
- 盘中 AI 正常工作，证据异常时首个 LLM 前失败关闭；
- 交易不消费复权价，回测不消费未来因子；
- API、前端、日志和健康检查展示同一状态与错误原因；
- 所有部门文档引用 ADR-013 和本计划，不存在第二套阈值或复权定义。
