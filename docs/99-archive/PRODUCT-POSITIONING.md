# 产品定位与数据战略

> **创建**：2026-07-23 | **状态**：🆕 战略定论
> **触发**：用户对竞品分析的系统性讨论后的明确方向定论

---

## 一、一句话定位

> **litchi-head 是一个散户 AI 投资决策副驾驶——告诉普通人在什么价格买、什么价格卖，帮你盈利。不做高频，不做社区，不为机构服务。**

---

## 二、明确不做的事（边界）

| 不做 | 原因 |
|:-----|:------|
| ❌ 不服务机构 | 产品定位是散户，不做 Wind/同花顺的机构客户 |
| ❌ 不做高频/秒级交易 | 我们的场景是日频/周频决策，不是量化 HFT |
| ❌ 不做社区/社交 | 不和东方财富股吧、雪球社区竞争 |
| ❌ 不做 6000 个指标的数据库 | 那是 Wind 的战场，散户不需要也看不懂 |
| ❌ 不做 Excel 插件 | 散户不用 Excel 做投资（机构才用） |
| ❌ 不追求 Level-2 毫秒行情 | 3-5 秒的 akshare 数据对日频决策完全够用 |

## 三、明确要做的事（核心价值）

| 做 | 为什么 |
|:---|:-------|
| ✅ **什么价格买** | 给出买入区间和建议，带置信度 |
| ✅ **什么价格卖** | 给出止盈/止损参考，带信号条件 |
| ✅ **让散户盈利** | 所有功能最终指向这个目标——不为了炫技加功能 |
| ✅ **数据够用、刚好够用** | 不堆数据，只取当前股票/行业最有效的指标 |
| ✅ **AI 推理替代人工分析** | 散户不需要自己算因子、不需要懂量化，AI 替你算好 |
| ✅ **置信度标注** | 每个建议标注可信程度，让散户知道"这个建议靠谱吗" |
| ✅ **决策可回溯** | 复盘看板——散户能回看 AI 过去的建议对不对 |

## 四、分析框架：三维一体

> **核心观点**：只知道"PE=15、ROE=20%"没有意义。必须知道这个公司在行业里的位置、上下游关系，才知道这些数字代表什么。

### 4.1 三维模型

```
┌──────────────────────────────────────────────┐
│            分析的三个维度                       │
├──────────────────────────────────────────────┤
│                                                │
│  ① 财务指标  ② 产业链定位  ③ 供应链关系          │
│  (What)      (Where)      (Who)               │
│                                                │
│  PE/PB/ROE   上游/中游/下游  前5大客户/供应商    │
│  毛利率/增长  议价权判断    集中度风险           │
│  现金流/负债  利润分配格局   替代威胁             │
│                                                │
└──────────────────────────────────────────────┘
```

> **三个维度必须一起看，才能做出正确的投资判断。**

### 4.2 产业链位置决定看什么指标

> 你选什么指标，取决于这个公司在产业链的什么位置。

| 位置 | 典型公司 | 关键指标 | 不看什么 |
|:-----|:---------|:--------|:---------|
| **🔺 上游**（原材料/矿） | 紫金矿业、万华化学 | 产能利用率、库存周期、大宗价格相关性、负债率 | 品牌溢价（B2B不需要） |
| **🔶 中游**（制造/加工） | 立讯精密、宁德时代 | 毛利率趋势、应收周转率、大客户集中度、研发费用 | 品牌溢价（B2B不需要） |
| **🔻 下游**（品牌/渠道） | 茅台、美的、美团 | 品牌溢价、渠道库存、用户留存率、现金流 | 研发费用（非科技不关键） |

**示例对比**：

```
宁德时代（中游制造）：
  产业链位置：电池制造，上游锂矿，下游车企
  关键看：毛利率趋势（被上下游挤压）、应收账款（车企回款慢）、研发（技术迭代快）
  不看：品牌溢价

茅台（下游品牌）：
  产业链位置：白酒品牌
  关键看：品牌溢价（出厂价vs批发价）、预收账款（经销商打款意愿）、库存（越存越值钱）
  不看：应收账款（先打款后发货）、研发费用
```

### 4.3 供应链关系决定风险

除了产业链位置，还要看上下游的**集中度**：

| 场景 | 风险 | 判断信号 |
|:-----|:-----|:---------|
| 前3大客户占营收 > 50% | 丢失一个大客户就崩 | 应收周转率恶化 |
| 前3大供应商占采购 > 50% | 供应商涨价就压利润 | 毛利率被动下降 |
| 客户/供应商极其分散 | 议价权在谁手里？ | 毛利率趋势 |
| 主要市场单一（如纯出口） | 贸易政策风险 | 营收地区分布 |

### 4.4 对散户的输出示例

**打开一个股票，系统应该告诉用户的是：**

```
"工商银行是银行，属于金融行业。
 生态位：吸收存款、发放贷款，赚利差。
 关键要看：净息差（赚不赚钱）、不良率（风险多大）、PB（便宜吗）
 不看：存货周转率（银行没存货）、毛利率（不适用）"

"宁德时代是动力电池制造商，处于新能源车产业链的中游。
 上游是锂/钴/镍矿，下游是车企。
 关键要看：毛利率趋势（上下游挤压程度）、应收账款周转率（车企回款周期）、
           研发费用率（技术迭代快）、大客户集中度（前3大占比）
 不看：品牌溢价（B2B业务）"
```

而非：

```
"工商银行有 22 个财务指标：
 PE=6.2, PB=0.6, ROE=10%, 毛利率=…, 存货周转率=…"
（一半不相关，散户分不清）
```

## 五、数据战略：动态指标选择

### 5.1 核心洞察

> **每个行业/股票有自己最敏感的 5-10 个核心指标。专业分析师不是看完 6000 个指标才做判断的。AI 应该模仿分析师的工作方式，而非模仿数据库。**

### 5.2 传统做法（不采用）

```
Wind/同花顺模式：
  所有股票 → 6000 个固定指标 → 用户自己筛选 → 决策
  问题：信息过载、门槛高、95% 的指标散户永远用不上

我们目前的模式（需要改进）：
  所有股票 → 22 个固定指标 → AI 推理 → 建议
  问题：比 Wind 好，但仍然是一刀切，对特定行业不够精准
```

### 5.3 动态指标选择（新战略）

```
我们（新战略）：
  股票 → 判断行业 → 判断产业链位置(上游/中游/下游) → 
  动态选择该行业+位置最关键的 5-10 个指标 → AI 推理 → 建议
```

**示例（行业 + 产业链位置联合决定指标集）：**

| 行业 | 产业链位置 | 核心指标 | 不关注 |
|:-----|:---------|:--------|:------|
| 🏦 银行 | 下游（金融中介） | 净息差、不良率、拨备覆盖率、PB、股息率 | 存货周转率、毛利率 |
| 🏭 制造业 | 中游 | 毛利率、存货周转率、ROE、负债率、PE | P/S |
| 💊 创新药 | 中游（研发） | 研发费用率、现金流、P/S、营收增长 | PE（亏损期无意义） |
| 🛒 消费零售 | 下游（品牌） | 营收增长、毛利率、周转率、PE、PEG | P/B |
| 🔋 新能源 | 中游/下游混合 | 产能利用率、营收增长、毛利率、PE、负债率 | P/B、流动比率 |
| 🏠 房地产 | 下游（开发） | 负债率、销售回款率、土储、PB | PE（周期股失真） |

### 5.4 技术实现路线

```
┌─ 股票信息 ───────────────────────┐
│  code → 行业 + 产业链位置          │
│  (BoardInfo + 主营业务构成)         │
└──────────────┬────────────────────┘
               ↓
┌─ 指标注册中心 ────────────────────┐
│  (industry, position) → [indicators]│
│  每个指标关联：                     │
│  - 数据来源（akshare 哪一列）        │
│  - 计算方式（直接取 / 组合算）       │
│  - 正常区间（异常检测用）            │
│  - 同行业对比基准值                 │
└──────────────┬────────────────────┘
               ↓
┌─ 动态采集引擎 ────────────────────┐
│  只拉注册表中当前股票需要的字段      │
│  不拉全部 86 列                    │
└──────────────┬────────────────────┘
               ↓
┌─ 上下文包装 ─────────────────────┐
│  "这是{行业}的{位置}公司           │
│   关键指标：{5-10个指标及其含义}"   │
└──────────────┬────────────────────┘
               ↓
┌─ AI 推理 ────────────────────────┐
│  基于行业上下文 + 关键指标做判断    │
│  输出：买入/卖出/持有 + 价格区间    │
└───────────────────────────────────┘
```

### 5.5 与当前架构的关系

- **保留** `DataSource Protocol` — 数据源抽象层不变
- **保留** `FinancialMetrics` — 作为所有可能字段的超集，不再要求全部填充
- **新增** `IndicatorRegistry` — (行业, 产业链位置) → 指标映射
- **新增** `DynamicIndicatorSelector` — 股票 → 行业+位置 → 选指标
- **修改** `DataCollector` — 支持按需拉取部分字段
- **基建已有**：`BoardInfo` 行业分类已有（`get_industry_boards()`）
- **待扩展**：产业链位置判断（需主营业构成或外部分类）

## 六、与竞品的核心差异总结

| 维度 | Wind/同花顺 | litchi-head |
|:-----|:-----------|:------------|
| **目标用户** | 机构 / 专业投资者 | **散户个人投资者** |
| **数据量** | 6000+ 指标（信息过载） | **5-10 个行业关键指标（刚好够用）** |
| **使用方式** | 手动筛选、Excel 公式 | **AI 自动推理、直接出建议** |
| **决策链路** | 数据 → 人工分析 → 决策 | **数据 → AI 分析 → 带置信度的建议** |
| **收费** | 1~4 万/年/终端 | **开源/低成本** |
| **速度** | 毫秒级（HFT 需要） | **秒级（日频决策足够）** |
| **社区** | 有（但不是核心差异化） | **不做社区** |
| **回测验证** | 用户自己算 | **AI 建议可回溯、可验证** |
| **产业链意识** | 有数据但需人分析 | **AI 自动识别产业链位置并据此选指标** |

## 七、战略原则

1. **"够用"优于"堆砌"** — 每次只拉 5-10 个指标，而不是 86 列全拉
2. **产业链位置优先** — 不看位置就看不懂指标，不搞一刀切
3. **结果导向** — 所有功能最终问："这个功能帮散户赚钱了吗？"没有就砍
4. **不炫技** — 不用复杂算法装点门面，AI 的推理要可理解、可信任
5. **置信度不是装饰** — 每个建议必须带可信度评估，散户知道自己面对的是什么级别的确定/不确定
