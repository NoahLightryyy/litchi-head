### TD-068 重型辩论无 durable queue、全局背压与恢复

| 属性 | 值 |
|------|-----|
| **分类** | `💻 implementation` `severity:moderate` `module:backend` `impact:容量与费用` |
| **发现日期** | 2026-07-28 |
| **发现人** | AI 审视 + 用户并发提问 |
| **状态** | `🔧 原型验证中` |
| **本金估算** | ∼2d |
| **日利息** | Agent 层数和用户入口增加后，LLM 并发、费用和失败恢复继续失控 |
| **实盘影响** | 多次点击或并发请求可能重复产生昂贵辩论；重启后运行中任务和结果全部丢失 |
| **触发场景** | 1 个以上重型辩论并发、后端重启、LLM 超时后重试、前端重复提交 |
| **用户能发现吗** | ⚠️ 部分能；会看到卡住或结果消失，但重复费用和重复执行可能不可见 |

**描述**：

`POST /api/debate/run` 在请求内等待完整 LangGraph；session 保存在无淘汰的进程
字典中。现有限流是每 IP 请求频率，不等于全局 Worker 并发预算，也不能恢复任务。

**修复方向**：

采用 SQL job/outbox + Redis 通知或 SQL durable queue；为任务增加幂等键、全局并发
上限、队列长度、取消、超时、重试和恢复；先通过 1/3/5 场并发成本门禁。

**2026-07-28 进展**：

已新增版本化 `DebateSessionRecord`、SQLite WAL 持久原型和恢复门禁。同一份
9,778-byte 代表性快照在 SQLite 与 PostgreSQL 17 上均通过提交后重启恢复和
SHA-256 一致性校验。Batch C 又验证了 68,896-byte 真实 LLM 结果的 SQLite
重开恢复，并用最小两节点图证明 LangGraph SQLite checkpoint 能跨连接续跑且
不重跑已完成节点。债务不关闭：后端路由仍使用进程内字典，正式辩论图尚未接入
checkpointer，durable queue、全局背压和 1/3/5 并发门禁仍未完成。

### TD-081 板块行业/概念上游串行超时导致接口最坏 30 秒

| 属性 | 值 |
|------|-----|
| **分类** | `💻 implementation` `severity:moderate` `module:backend/market` `impact:首页可用性` |
| **发现日期** | 2026-08-28 |
| **发现人** | AI 浏览器实测 |
| **状态** | `🆕 待评估` |
| **本金估算** | ∼2h |
| **日利息** | 两个上游都异常时，每次首页板块请求都长期占用后台线程并拖慢反馈 |
| **实盘影响** | 板块榜在行情来源异常时不能及时给出结果，用户可能误以为整个应用卡死 |
| **触发场景** | 行业板块和概念板块两个 AKShare 上游均连接失败或各自达到 15 秒超时 |
| **用户能发现吗** | ✅ 能；前端现会在 18 秒后结束骨架屏并显示可重试失败态，但后台慢请求仍存在 |

**描述**：

`GET /api/market/sectors` 依次等待行业与概念两个 `run_sync()`；每路超时上限 15 秒，
最坏时延约 30 秒。前端已用有限等待保护用户体验，但没有消除服务端线程和时延成本。

**修复方向**：

在不改变冻结响应契约的前提下并发收集两路板块来源，并为整次聚合设置统一截止时间；
补充双超时、单路成功和取消后的线程占用门禁，再重新走消费者与真实浏览器验收。
