# 📐 质量保障部技术规范

> 本文件定义质量保障部自身的标准。全局 CI 门禁标准见 `docs/01-guides/ci/STANDARDS.md`。

---

## 1. CI 问题管理标准

### 问题生命周期

```
发现 → 登记 (ISSUES.md / DEBT.md) → 定位 → 修复 → 验证 → 复盘 → 关闭
```

### ID 命名

- CI 系统问题：`CI-NNN`（如 CI-001）
- 与其他部门债务关联：在关联部门 DEBT.md 中加引用

### 严重度分级

| 级别 | 定义 | 响应时间 |
|:----:|:-----|:--------:|
| P0 🔴 | 所有版本失败（3.12 + 3.13 全红） | **立即**，当前批次内 |
| P1 🟡 | 单版本失败 | **当前批次内** |
| P2 🟢 | 非阻塞项（pip-audit 警告、3.13 超时） | **本次迭代内** |

## 3. 跨部门协作标准

### CI 红了，谁修？

```
CI 红了
├── 根因在 CI 系统本身（runner 挂了、超时太短、配置错误）
│   └── → 质量保障部修
├── 根因在基础设施（依赖装不上、Python 版本不对）
│   └── → 通知基础设施部
└── 根因在业务代码（测试失败、类型错误、lint 报错）
    └── → 通知对应部门修
          └── 质量保障部负责"追"——红了没修 → 质量保障部的债
```

### 数据契约变更通知

质量保障部不生产数据契约，但 CI 配置变更（检查项增减、超时调整）影响所有部门。

### K 线跨部门验收矩阵

质量保障部按
[K 线实施计划](../../02-requirements/KLINE_EVIDENCE_IMPLEMENTATION_PLAN.md) 独立验收：

| 类别 | 必测 |
|:--|:--|
| 来源 | 相同 `upstream_id` 不重复计数；沪深双源；北交所缺第二源失败 |
| RAW | 代码/市场/日期/周期/币种；一 `price_tick` 差异进入冲突 |
| 单位 | 股/手归一化；只允许已声明精度内差异 |
| 复权 | RAW/因子/派生分层；除息、送转、配股、因子修订 |
| 点时 | 回测无法读取未来因子；结果可按版本重放 |
| 状态 | 四层状态不互相混入；收盘晋升幂等 |
| AI | 所有必需证据失败时分析师、大师 LLM 调用数为零 |
| 交易 | 前复权/后复权价格不能进入订单坐标 |
| API/UI | 稳定错误码；口径、时间、来源不足和冲突用户可见 |
| 运维 | 来源超时、限流、断网、字段损坏和恢复均有指标/日志 |

实时报价 0.01 元容差、分钟累计量 500 股经验容差和完成日线严格 RAW 对账必须有
不同测试套件和配置名。任何跨用均视为 P0 契约缺陷。
