### TD-071 AKShare CNINFO 在零公告窗口抛错

| 属性 | 值 |
|------|-----|
| **分类** | `💻 functionality` `severity:moderate` `module:data-provider` `impact:权威公告可用性` |
| **发现日期** | 2026-07-28 |
| **发现人** | AI 真实来源烟测 |
| **状态** | `⚠️ 待接入路线决策` |
| **本金估算** | ∼2–4h |
| **日利息** | 正常无公告窗口会被视为来源失败，未来可能阻断完整证据链 |
| **实盘影响** | 系统可能因为“没有新公告”而拒绝本可正常进行的分析，造成机会延误 |
| **触发场景** | `stock_zh_a_disclosure_report_cninfo` 查询窗口内 `totalAnnouncement=0` |
| **用户能发现吗** | ✅ 接入失败关闭后会看到来源失败；但无法自行判断其实只是零公告 |

**描述**：

2026-07-28 真实烟测中，平安银行 7 月 27–28 日短窗口没有公告。AKShare 在空
DataFrame 上强制选择固定列并抛出 `KeyError`，新适配器正确返回 `FAILED`，没有
误报为 `SUCCESS_EMPTY`。扩大到 6 月 1 日–7 月 28 日后成功取得 3 条公告，证明
有数据链路、公告编号和字段映射正常。

**具体问题**：

1. ❌ 当前无法可靠区分“巨潮明确返回零条”与“AKShare 包装层解析失败”；
2. ❌ 若把该异常直接视为空结果，会掩盖真正的上游字段变更；
3. ❌ 若保持失败关闭，正常无公告日会造成不必要的业务阻断。

**修复方向**：

1. 优先评估直接调用巨潮公开查询端点，显式读取 `totalAnnouncement=0`；
2. 或等待 AKShare 对空结果的正式修复并锁定已验证版本；
3. 两条路线都必须保留真实烟测和故障注入测试，不能按异常文本猜测空结果。
