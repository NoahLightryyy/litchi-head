### TD-069 核心行情缺失仍执行完整 LLM 辩论

| 属性 | 值 |
|------|-----|
| **分类** | `💻 implementation` `severity:moderate` `module:debate+data` `impact:实盘可信度与运行时成本` |
| **发现日期** | 2026-07-28 |
| **发现人** | AI 真实辩论门禁 |
| **状态** | `🔧 修复中（产品策略已确认）` |
| **本金估算** | ∼1d |
| **日利息** | 每次数据源降级都可能产生看似完整但证据残缺的昂贵分析 |
| **实盘影响** | 用户可能把缺少实时行情、新闻或行业数据的结论当作完整分析，影响真金白银判断 |
| **触发场景** | 东方财富代理失败、新闻解析失败、行业数据源失败，但编排器仍继续运行 |
| **用户能发现吗** | ❌ 当前结果页不显式展示输入完整度；日志可见，但普通用户看不到 |

**描述**：

2026-07-28 对 `000001` 的真实门禁中，实时行情、新闻和行业数据均出现采集错误，
但编排器仍完成 16 次 LLM 调用、耗时约 176 秒并返回成功结果。结果结构完整不等于
输入证据完整，当前既缺少成本短路，也缺少面向用户的数据完整度声明。

**具体问题**：

1. 核心输入没有“必需 / 可选”分级和统一完整度契约；
2. 数据降级不会在开始昂贵 LLM 链前形成明确决策点；
3. `DebateResult` 和前端没有展示缺失来源、数据时间和降级状态；
4. 系统无法区分“允许降级的研究”与“必须拒绝的实盘辅助分析”。

**已确认修复方向**：

- 实时行情、K 线、新闻和行业证据均为完整业务链必需项，不允许自动降级；
- 在 LLM 调用前失败关闭，证据不完整时 LLM 调用数必须为零；
- 每类数据使用多个真实上游，统一格式后交给业务层；
- 成功空结果与采集失败必须严格区分；
- 2026-07-28 已完成 `src/data/evidence.py` 基础契约和 10 项测试；
- 2026-07-28 已完成首个 CNINFO 适配器基础和 10 项测试；真实有数据链路通过，
  但零公告窗口受 AKShare 缺陷影响，见 TD-071；
- 后续仍需接入首批免费来源、`DataEvidenceService`、正式辩论图和用户可见错误。
