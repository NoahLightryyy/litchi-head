- 旧 `actual_return_pct` 是“辩论价到观察价”的市场涨跌，缺少成交、数量、费用与

- `src/debate/mirror.py` 的 `MirrorReport` 比较大师历史观点，不是用户行为镜子；前端
  也没有用户行为镜子的完整消费闭环。
- 旧 0 分或 0 置信度记录未经核验不能成为有效 AI 样本；缺值不得补零。

## 第一批冻结契约

- `POST /api/user/action`：`X-User-Id` + `client_action_id` 提供用户逻辑隔离与幂等；
  相同事实重试回放，复用标识提交不同事实返回 409。
- `GET /api/user/actions`：只能在指定用户内查询，支持股票、会话和分页过滤。
- 事件时间必须带时区；数量、成交价均可缺失但不得补零；成交价存在时币种必须显式。
- `ai_decision_id` 只保存引用，当前统一标为 `unverified`，不得进入正式 AI 效果样本。
- 账本失败返回 503 且允许使用相同幂等键重试；写入成功后回调失败不回滚事实事件。
- 旧 `/api/retro/*` 暂留兼容并标记 deprecated；其收益字段明确为市场变化而非账户盈亏。

## UA-03 决策记录审计与已冻结校验语义

| 审计项 | 现有可复用事实 | 缺口与处理 |
|:-------|:---------------|:-----------|
| 原始观点 | `DebateResult.analyses` 保存结构化全文、摘要、证据文字、评分与置信度 | 以排序稳定的 canonical JSON 生成 `original_viewpoints_sha256`，不只引用聚合分数 |
| 会话事实 | `DebateSessionRecord` + `measure_session_snapshot()` 可生成完整信封 SHA-256 | 正式路由仍使用进程内字典，TD-068 未关闭 |
| 模型版本 | LLM 层运行时知道模型名，CostTracker 有会话/Agent 用量 | 尚未绑定进 `DebateResult`；缺任一成功 Agent 的模型版本即不合格 |
| Prompt 版本 | Prompt 在编排代码中可定位 | 没有稳定版本/哈希；缺任一成功 Agent 的 Prompt 版本即不合格 |
| 配置/代码版本 | Git 和配置文件本身可取得 | 决策记录未保存；缺失即不合格 |
| 时间 | session 有创建/更新时间 | 不能代替明确 `decided_at`；生产方必须提供带时区决策时间 |
| 证据引用 | 分析有 `key_evidence`，结果有 `evidence_limitations` | 文字和限制不是可核验引用；必须提供来源、`as_of` 与内容哈希 |

新增 `verify_ai_decision_reference()` 与 `AiDecisionReferenceLedger`：

- 用户操作事件保持不可变；每次核验另追加一条关联事实，并绑定完整 session SHA-256、
  原观点 SHA-256 和版本血缘；相同事实幂等回放、篡改冲突。
- `completed`、会话/股票身份一致、正的投票数/聚合评分/置信度、全部 Agent 成功且其
  评分/置信度为正，以及完整模型/Prompt/配置/代码/证据版本，必须同时成立才能标记
  `eligible_for_effect_sample=true`。
- 所有旧记录默认缺 provenance，因此即便有正分也为 `ineligible`；零分、失败请求或
  未核验证据引用绝不自动接纳。每个失败原因均保存机器码，不能静默补零。
- 当前不开放“客户端上传 provenance 后自行验证”的写接口，避免客户端自证。待辩论
  生产方把服务端实际版本写入 durable session 后再接 API；这是 TD-090/TD-068 的边界。

## UA-04 账户结果事件审议草案（尚未冻结）

真实上报与模拟假设必须分成不同事件族，不能共用一个“实际收益”字段：

- `ReportedExecutionEvent`：用户或未来券商适配器报告的成交/撤单/拒单事实。最少含
  `account_ref`、证券、买卖方向、数量、成交价、币种、成交时间、来源和外部成交号；
  手续费、税费缺失保持 `null`，不解释为 0。
- `ValuationObservationEvent`：在明确时点、来源和价格类型下对未平仓头寸估值；这是
  浮动观察，不是已实现盈亏。
- `SimulationAssumptionSet`：回测/假设使用的费率、滑点和不可成交规则，必须有版本，
  绝不冒充真实上报费用或成交。

需要用户集中选择的口径如下；在确认前不写入生产默认值：

| 决策 | 选项 | 影响 |
|:-----|:-----|:-----|
| 收益基准 | A. 已平仓 lot 成本后收益；B. 现金流 XIRR；C. 两者分列 | A 易审计但跨期资金不可比；B 可比但对现金流完整性要求高；C 信息最全、实现与解释成本最高 |
| 未平仓处理 | A. 仅展示浮盈；B. 纳入分时总收益但单列已实现/未实现 | A 最保守；B 更完整但必须冻结估值时点与价格来源 |
| 主 benchmark | A. 用户为每个策略指定指数；B. 证券所属宽基映射；C. 现金/无风险基线 | A 最符合意图但需用户配置；B 自动化但映射会改变结论；C 只回答是否优于持币，不回答是否跑赢市场 |
| 费用 | A. 每笔真实上报；B. 券商账单导入；C. 版本化费率估算且明确 estimated | A 精确但录入重；B 最可审计但需适配；C 可补分析但不能标为真实费用 |
| 滑点 | A. 成交价对决策时可交易报价；B. 对到达市场时的报价；C. 不计算 | A 衡量整条决策链；B 更聚焦执行；两者都要求同证券、同方向、带来源时间的报价，否则为 unknown |
| 统计窗口 | A. lot 平仓生命周期；B. 固定 1/5/20 交易日；C. 两者并行 | A 对真实账户自然；B 便于同批比较但会含未平仓估值；C 完整但报表更复杂 |
| 不可成交 | A. 独立 `rejected/cancelled/partial_fill` 事件并进入完整分母 | 防止只统计成功成交造成幸存者偏差；拒单原因不得推断 |

推荐审议顺序：先定真实成交事件与费用来源，再定收益基准/未平仓口径，最后定 benchmark、
滑点参考和窗口。账户认证与账户标识脱敏是接入生产前置条件。
