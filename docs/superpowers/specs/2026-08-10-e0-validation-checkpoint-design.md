# E0 Validation-First Checkpoint 设计

> **状态**：用户已批准设计；尚未进入实施计划。
> **日期**：2026-08-10
> **范围**：首轮 100 条离线历史决策评测，只用于证伪与决定是否扩大样本。
> **战略约束**：暂停自动进入 KR-4；不新增 Agent、部门、市场或通用实验平台。

## 1. 目标与非目标

E0 回答一个窄问题：在相同历史时点证据和相同 DeepSeek 模型下，完整 Litchi Head
是否比单 Agent、简单规则和被动暴露表现出值得继续验证的增量价值。

E0 是闭卷评测，不是训练、微调或 Prompt 优化。100 条正式样本不得用于调参，运行后
也不得依据结果更换主周期、样本或对照。E0 只允许三类业务结论：停止扩建、扩大样本、
证据不足。任何结果都不得宣传为实盘效果已经得到证明。

E0 明确不做：

- 不接入 GPT、Claude 或 Gemini；只有 E0 证明多 Agent 架构值得继续后，才进行模型供应商横向比较；
- 不接券商 App、不自动下单、不模拟融券做空；
- 不修改生产 Agent、Prompt、权重或风险默认值；
- 不接 API 或前端，不建设通用模型治理/实验平台；
- 不移动现有代码、目录或部门文档，不新增组织层级；
- 不用 100 条样本声称 Sharpe、校准或未来收益已经稳定成立。

## 2. 两阶段验证顺序

旧 TD-074 把所有验证放在 KR-6 之后；本设计按已批准战略拆成两阶段：

1. **E0 离线证伪**：在 KR-4 前运行 100 条冻结历史时点题，先检验现有复杂架构是否值得继续建设。
2. **E1 在线影子验证**：只有生产链 KR-4～KR-6 完成后，才连续运行 4～8 周的不可变影子样本，进入 S0/S1/S2 证据阶段。

E0 通过不代表 TD-074 关闭；它只解除“是否值得继续扩大样本或完成下游生产链”的前置疑问。

## 3. 样本单位与冻结题集

一条正式样本是一个冻结的：

`股票代码 + 决策时间 + 当时可见证据快照 + 5 个交易日主周期`

首轮题集共 100 条，采用以下规则：

- 股票必须属于决策时点当时的沪深 300 成分股，不能用今天的成分股回填；
- 上涨、下跌、震荡、高波动四种市场状态各 25 条；状态分类只能读取决策时点以前的数据；
- 同一股票最多 2 条，同一交易日最多 5 条；
- 抽样算法、随机种子、候选全集、排除原因和最终清单必须在参赛器运行前冻结；
- 未来 1/5/20 日行情只对标签器可见，所有参赛器均不得读取；
- 失败、超时、拒答、停牌、不可成交和数据缺口必须保留在分母；
- 正式题集不得用于训练、Prompt 调整、权重调整或规则参数选择。

市场状态的具体数学分类必须以一个带版本的 `RegimePolicy` 写入实验清单。系统不得提供
隐含默认；首次真实抽样前必须将公式和阈值单独提交用户确认。若样本因未来信息、哈希
错误或重复身份而无效，只能按清单中预注册的替补顺序补位，不能人工挑选替代样本。

## 4. 五个参赛器

| ID | 参赛器 | 冻结规则 |
|:--:|:-------|:---------|
| A0 | 完整 Litchi Head | 使用当前生产式多 Agent/辩论流程，不为评测修改行为 |
| A1 | 单 Agent DeepSeek | 与 A0 使用同一 DeepSeek 模型、同一冻结证据、同一输出契约和 5 日目标 |
| B0 | 现金/不行动 | 始终保持现金 |
| B1 | 买入持有 | 在可成交时按统一仓位买入并持有到标签日 |
| B3 | 20 日动量 | 决策时点过去 20 个交易日收益为正则持有，否则现金；固定等权且不调参 |

A0 与 A1 不强行使用相同 Token 数。二者记录实际 Token、费用和延迟，先比较真实产品
表现，再报告每单位成本的增量。A1 不得读取 A0 的中间发言或结果。

所有参赛器只允许做多或持有现金。AI 的 `SELL` 表示卖出已有仓位或保持空仓，不建立负仓位。

## 5. 统一决策契约

每个参赛器对每条题必须产生一条不可变 `DecisionRecord`，至少包含：

- `experiment_id`、`sample_id`、`runner_id` 和唯一版本身份；
- 股票、决策时间、证据快照 ID、证据哈希和 `as_of`；
- `LONG`、`CASH` 或 `ABSTAIN`，以及统一仓位；
- LLM 参赛器的原始置信度和拒答/失败原因；
- 模型、Prompt、代码提交、配置、策略和成本配置版本；
- 开始/结束时间、延迟、Token、模型费用和信息新鲜度；
- `COMPLETE / ABSTAIN / FAILED / TIMEOUT` 运行状态。

状态不是过滤条件。四种状态全部进入实验分母，单个参赛器失败时不得由另一个模型代答。

## 6. 标签、成本与真实券商费率

5 个交易日是唯一主周期；1 日和 20 日只作为辅助结果，不能事后改为主结果。

标签器必须使用点时 RAW/复权证据生成统一的 1/5/20 日结果，并显式记录停牌、涨跌停和
不可成交事实。所有参赛器使用相同价格坐标、成交时点和成本规则。

E0 实现不内置隐含交易费率。每次真实实验必须提供一个显式、带版本的 `FeeProfile`；
缺失时命令直接拒绝运行。首轮采用用户单独确认的保守费率配置。后续可以增加交割单导入：

- 根据实际成交额和费用反推券商佣金、最低收费与其他费用；
- 每家券商和每次费率变化生成新版本；
- 切换券商不覆盖历史实验的旧费率；
- 识别证据不足时标记待确认，禁止按券商名称静默猜测。

券商 App 抓取和通用券商适配不属于 E0。

## 7. 指标与稳定性审计

主比较是 A0 对 A1 的 5 日成本后逐题配对结果。结果表必须同时报告：

| 维度 | 指标 |
|:-----|:-----|
| 预测 | 方向准确率、平衡准确率、Brier、ECE、置信度分桶正确率 |
| 经济 | 成本后收益、相对收益、Sharpe、最大回撤、hit rate、盈亏比、换手率 |
| 安全 | 高置信度错误率、尾部损失、最坏单笔/连续损失、拒答覆盖率、硬门禁越过次数 |
| 运行 | 成功/失败/超时率、信息新鲜度、延迟、Token、单次决策成本 |
| 分层 | 1/5/20 日、四种市场状态及完整分母 |

B0、B1、B3 用于解释绝对价值和低成本替代，不取代 A0/A1 的架构增量比较。

稳定性审计从正式 100 条中按冻结随机种子选择 20 条。A0 与 A1 各独立运行 3 次，报告
方向、仓位和置信度的变化；不为降低成本而事后更换审计子集。

## 8. E0 裁决

E0 不使用单一收益指标，也不要求 100 条就达到传统显著性门槛。

### 8.1 实验无效

存在任一情况即整轮无效：未来信息泄漏、题集/版本未冻结、删除失败样本、硬门禁绕过、
标签提前可见、清单哈希不一致或旧记录被覆盖。

### 8.2 停止扩建并进入消融

当 A1 在 5 日成本后收益、Brier、高置信度错误率和最大回撤上均不差于 A0，且至少两个
质量/风险指标严格优于 A0，同时 A0 的成本或延迟不低于 A1，判定 A0 被整体支配。

该结论不允许立即删除模块；下一步只运行预注册的单变量消融，定位应削减的层级。

### 8.3 扩大到 300～500 条

当 A0 的 5 日成本后逐题配对收益高于 A1，至少一个 Brier/ECE/高置信度错误指标改善，
且最大回撤、尾部损失和硬门禁没有恶化，允许冻结同一方案并扩大样本。

### 8.4 证据不足

其他组合一律记录为证据不足。不得选择性强调某一指标宣布成功；只能扩大样本，或在不
查看正式答案的前提下修复明确的实现缺陷并开启新实验版本。

## 9. 最小代码落位

E0 由现有回测研究能力承接，不新增常设系统：

- `src/backtest/`：E0 Pydantic 契约、参赛器适配、标签和配对评测；
- 复用 `src/backtest/metrics.py` 的现有绩效指标；
- 复用 `src/debate/trust.py` 的 Brier/校准计算口径，不实现第二套；
- `scripts/`：一个 E0 命令行入口；
- `data/benchmarks/e0/<experiment_id>/`：每轮不可变实验产物。

每轮目录最少包含：

- `manifest.json`：题集、版本、成本、随机种子和哈希；
- `decisions.jsonl`：所有参赛器的全部状态；
- `labels.jsonl`：1/5/20 日标签及不可成交事实；
- `report.json`：机器可读结果；
- `report.md`：唯一的人类结果表。

写入采用临时文件加原子替换；已有终态实验不得覆盖。中断后只能依据冻结记录幂等续跑。

## 10. 错误处理与测试

- 单样本模型异常归类为 `FAILED`，超时归类为 `TIMEOUT`，保留稳定错误码和可见日志；
- 题集、版本、哈希、未来信息或标签隔离错误属于实验级失败，停止整轮；
- 不允许静默回退到其他模型、当前数据或默认成本；
- 报告生成只读冻结产物，不调用 LLM 重新解释历史结果。

验证分层：

1. 单元测试：抽样上限、成本、标签、配对指标和裁决真值表；
2. 契约测试：五个参赛器读取同一证据并输出同一 `DecisionRecord`；
3. 防作弊测试：未来数据、删失败样本、manifest 篡改和终态覆盖必须失败；
4. 5 条无真实 LLM 的 deterministic dry-run 验证端到端产物；
5. 真实 E0-100 手工启动并保存完整报告，不放入 CI，也不自动改写项目结论。

## 11. 实施前仍需单独批准的运行参数

以下不是隐含默认，也不阻塞编写实现计划；它们必须在首次真实 E0 运行前形成独立、可
审计的用户批准记录：

- `RegimePolicy v1` 的数学公式与阈值；
- `FeeProfile v1` 的具体数值；
- 统一仓位比例和初始名义资金；
- 高置信度分桶边界；
- 300～500 条扩样的确切样本数。

实现必须在这些参数缺失时拒绝真实运行，测试只能使用显式 fixture。

## 12. 设计验收标准

- 能在不修改生产 Agent 的前提下生成第一张可信、完整分母的比较表；
- A0/A1 使用同一 DeepSeek、同一证据、同一目标和输出契约；
- 100 条题集在运行前冻结，未来数据与标签对参赛器不可见；
- 失败、拒答、超时和不可成交全部入账；
- 主周期、对照、规则和裁决不能事后切换；
- 不新增组织结构、券商集成、前端或通用评测平台；
- E0 结果只决定停止、扩样或证据不足，不宣称真实投资效果已验证。
